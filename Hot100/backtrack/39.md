This problem can be effectively solved using an algorithmic technique called **Backtracking**.

Because you can reuse the same numbers an unlimited number of times, we can think of this as exploring a decision tree. At each step, we have two choices to prevent duplicate combinations from forming:

1. **Include the current number:** Add the number to our combination and try to match the remaining target (staying at the same index so we can potentially use it again).
2. **Skip the current number:** Move on to the next available number in the array and never look back at the current one for this path.

---

### Step-by-Step Walkthrough

Let's trace how the decisions look for candidates = [2, 3] and target = 5:

1. **Start at Index 0 (Value 2):** Current Sum: 0, Target Left: 5.
We choose to include 2.

* Current combination: [2]
* Target remaining: $5 - 2 = 3$


2. **Stay at Index 0 (Value 2):** Current Sum: 2, Target Left: 3.
We choose to include 2 again.

* Current combination: [2, 2]
* Target remaining: $3 - 2 = 1$


3. **Stay at Index 0 (Value 2) -:**
Hit Dead End" subtitle="Current Sum: 4, Target Left: 1">
If we try to add 2 again, target becomes $-1$. That's less than 0, which means we went too far!

* **Backtrack:** We undo the last choice, removing 2. We return to [2, 2] and choose option 2: skip index 0 and move to index 1 (Value 3).


4. **Move to Index 1 (Value 3) -:**
Success!" subtitle="Current Sum: 4, Target Left: 1">
We try adding 3 to our combination [2, 2].

* Current combination: [2, 2, 3]
* Target remaining: $1 - 3 = -2$ (Over-shot! Backtrack again).
* *Alternative path:* What if at step 2 ([2], Target Left: 3), we chose to skip 2 and try 3?
* Current combination: [2, 3]
* Target remaining: $3 - 3 = 0$. **Bingo!** We save [2, 3] to our results.

### Python Code Implementation

Here is the clean backtracking approach implemented in Python:

```python
def combinationSum(candidates: list[int], target: int) -> list[list[int]]:
    results = []

    def backtrack(index: int, current_combination: list[int], remaining_target: int):
        # Base Case 1: We found a valid combination that hits the target exactly
        if remaining_target == 0:
            results.append(list(current_combination))  # Make a copy of the combination
            return
            
        # Base Case 2: We overshot the target or ran out of candidate numbers
        if remaining_target < 0 or index >= len(candidates):
            return

        # Choice 1: Include candidates[index] in our current combination.
        # Notice we don't increment 'index' because we can reuse this number.
        current_combination.append(candidates[index])
        backtrack(index, current_combination, remaining_target - candidates[index])
        
        # BACKTRACK: Remove the number we just added so we can try alternative paths
        current_combination.pop()

        # Choice 2: Skip candidates[index] entirely and move to the next number
        backtrack(index + 1, current_combination, remaining_target)

    # Start the recursive exploration from index 0 with an empty collection
    backtrack(0, [], target)
    return results

```

---

### Why the Backtrack Step Matters

The line current_combination.pop() is the core magic of backtracking.

When the function finishes exploring all options that start with [2, 2, ... ], it needs to go back up the tree to test paths that start with just [2, 3, ... ]. To do that, it must "clean up" after itself by popping the last 2 off the list. This keeps our memory footprint small because we reuse the exact same array throughout the entire process.

### Complexity Analysis

* **Time Complexity:** $O(N^{\frac{T}{M} + 1})$ where $N$ is the number of candidates, $T$ is the target value, and $M$ is the minimum value among candidates. The max depth of the tree is $\frac{T}{M}$ levels, and at each node, we branch into 2 choices.
* **Space Complexity:** $O(\frac{T}{M})$ to store the recursion stack and the tracking array for the longest possible combination path.
