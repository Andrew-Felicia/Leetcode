This problem has two fascinating restrictions: you **cannot modify the array**, and you must use **constant $O(1)$ extra space**. This eliminates sorting or using a hash set.

To find the duplicate under these conditions, we can treat the array as a **linked list** where each index points to the value stored at that index. Because there's a duplicate number, multiple indices will point to the exact same value, creating a **cycle** in our pointers.

We can solve this in linear $O(n)$ time using **Floyd's Tortoise and Hare (Cycle Detection) algorithm**.

---

### Phase 1: Detecting the Cycle

We use two pointers: a tortoise (slow pointer) that moves 1 step at a time, and a hare (fast pointer) that moves 2 steps at a time. Because a loop exists, the fast pointer will eventually trap and lap the slow pointer inside the cycle.

* **Move Slow:** slow = nums[slow]
* **Move Fast:** fast = nums[nums[fast]]

```
nums = [1, 3, 4, 2, 2]
Index:  0  1  2  3  4

```

1. **Initialization:** Both pointers start at index 0..
slow = 0, fast = 0


2. **Step 1:** Slow goes to index 0's value. Fast goes to index 0's value's value..
slow = nums[0] = 1

fast = nums[nums[0]] = nums[1] = 3


3. **Step 2:** Pointers continue tracing values as array jumps..
slow = nums[1] = 3

fast = nums[nums[3]] = nums[2] = 4


4. **Step 3:** The Hare loops around while Tortoise crawls ahead..
slow = nums[3] = 2

fast = nums[nums[4]] = nums[2] = 4


5. **Step 4 (Intersection):** They land on the exact same value!.
slow = nums[2] = 4

fast = nums[nums[4]] = nums[2] = 4

**They match!** We break out of the loop.


---

### Phase 2: Finding the Entrance of the Cycle

Once they intersect, we leave the slow pointer right where it is, but reset the fast pointer back to index 0.

Now, we move **both pointers at the exact same speed** (1 step at a time). The exact spot where they meet up again is guaranteed to be the duplicate number.

```python
def findDuplicate(nums: list[int]) -> int:
    # Phase 1: Find the intersection point of the two runners
    tortoise = nums[0]
    hare = nums[0]
    
    while True:
        tortoise = nums[tortoise]          # Moves 1 step
        hare = nums[nums[hare]]            # Moves 2 steps
        if tortoise == hare:
            break
            
    # Phase 2: Find the entrance to the cycle (the duplicate)
    tortoise = nums[0]                     # Reset one pointer to the start
    while tortoise != hare:
        tortoise = nums[tortoise]          # Both move 1 step now
        hare = nums[hare]
        
    return tortoise

```

---

### Proving a Duplicate Must Exist (The Follow-Up)

The mathematical proof that a duplicate *must* exist comes from the **Pigeonhole Principle**.

> **The Pigeonhole Principle states:** If you have $N$ pigeonholes and $N + 1$ pigeons, and you put every pigeon into a hole, at least one hole must contain more than one pigeon.

In this problem:

* Our "pigeons" are the items in the array (there are $n + 1$ integers).
* Our "pigeonholes" are the possible numeric values allowed by the constraints (values from $1$ to $n$, which is exactly $n$ slots).

Because the number of integers ($n + 1$) is strictly greater than the number of unique labels available ($n$), it is mathematically impossible to fill the array without repeating at least one value.

### Complexity Analysis

* **Time Complexity:** $O(n)$ — Both Phase 1 and Phase 2 traverse a linear distance across the elements.
* **Space Complexity:** $O(1)$ — We only created two pointer variables, meeting the constant auxiliary memory limit.
