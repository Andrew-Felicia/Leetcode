This is the classic **Jump Game II** problem. The most elegant and efficient way to solve it is by using a **Greedy Strategy** in $O(n)$ time.

Instead of trying to simulate every single possible jump sequence (which takes too long), think of this like a series of **"leaps"** or **"waves."** From your current position, you look at all the places you can reach with your *next* single jump, and you figure out what the absolute furthest point is you could reach on the *following* jump.

---

### The Strategy: Thinking in "Farthest Horizons"

Imagine you are standing at index 0. We keep track of three things as we walk through the array:

1. `jumps`: How many jumps we have actually committed to making so far.
2. `current_end`: The furthest index we can possibly reach with our *current* number of jumps. (This is the boundary of our current "wave").
3. `farthest`: The absolute furthest index we could ever reach if we jumped from *any* of the stepping stones we've passed through so far.

As we step from index `i` up to `current_end`:

* We constantly update `farthest = max(farthest, i + nums[i])`.
* When our footsteps finally reach `current_end`, it means we have exhausted all options for our current jump. We **must** make another jump to keep going.
* So, we increase `jumps` by 1, and we set our new `current_end = farthest`.

We stop this process right before the very last element, because once our `current_end` reaches or passes the last index, we don't need to jump anymore!

---

### Visualizing Example 1: `nums = [2, 3, 1, 1, 4]`

Let's trace it step-by-step:

* **Start:** `jumps = 0`, `current_end = 0`, `farthest = 0`
* **`i = 0` (value 2):**
* Furthest we can reach from here is $0 + 2 = 2$. So `farthest` becomes **2**.
* We hit `current_end` (which was 0)!
* Time to jump! `jumps` becomes **1**. Our new boundary `current_end` becomes **2**.


* **`i = 1` (value 3):**
* Furthest we can reach from here is $1 + 3 = 4$. Our `farthest` updates to **4**.
* We haven't hit our boundary `current_end` (2) yet, so we don't increment jumps.


* **`i = 2` (value 1):**
* Furthest we can reach from here is $2 + 1 = 3$. Our `farthest` stays **4** (since 4 is bigger than 3).
* We hit our boundary `current_end` (2)!
* Time to jump! `jumps` becomes **2**. Our new boundary `current_end` becomes **4**.


* **End of Loop:** We stop tracking here because we don't check the last index. The answer is `jumps = 2`.

### Python 3 Implementation

```python
class Solution:
    def jump(self, nums: list[int]) -> int:
        if len(nums) <= 1:
            return 0
        
        jumps = 0
        current_end = 0
        farthest = 0
        
        # We loop up to len(nums) - 1 because we don't need to jump 
        # once we are already standing on the last index.
        for i in range(len(nums) - 1):
            # Update the absolute furthest index we can reach from anywhere 
            # we've been so far
            farthest = max(farthest, i + nums[i])
            
            # If we've reached the end of our current jump's reach
            if i == current_end:
                jumps += 1
                current_end = farthest
                
                # Optimization: If we can already reach the end, stop early
                if current_end >= len(nums) - 1:
                    break
                    
        return jumps

```

### C++ Implementation

```cpp
#include <vector>
#include <algorithm>

class Solution {
public:
    int jump(std::vector<int>& nums) {
        int n = nums.size();
        if (n <= 1) return 0;
        
        int jumps = 0;
        int current_end = 0;
        int farthest = 0;
        
        for (int i = 0; i < n - 1; ++i) {
            farthest = std::max(farthest, i + nums[i]);
            
            if (i == current_end) {
                jumps++;
                current_end = farthest;
                
                if (current_end >= n - 1) {
                    break;
                }
            }
        }
        
        return jumps;
    }
};

```

---

### Complexity Analysis

* **Time Complexity:** $O(n)$ — We only pass through the array exactly once.
* **Space Complexity:** $O(1)$ — We are only storing a few integer pointers, making it highly memory efficient.
