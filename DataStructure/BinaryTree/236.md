To find the Lowest Common Ancestor (LCA) of two nodes in a standard binary tree, we can use a straightforward Depth-First Search (DFS) approach.

The intuition relies on a simple rule: if you are standing at a node, and one of your targets ($p$ or $q$) is somewhere in your left subtree, and the other target is somewhere in your right subtree, then **you must be their Lowest Common Ancestor**.

---

### The Recursive Strategy

When we run our recursive function on a node, it will return one of three things:

1. **`None`** if neither $p$ nor $q$ exists in that subtree.
2. **The node itself** if the current node happens to be either $p$ or $q$.
3. **The LCA node** if it was already found deeper down.

Here is exactly how the logic propagates up the tree:

1. **Base Cases:** Check current node.
If the current node is `None`, or if it matches either `p` or `q`, return the current node immediately.


2. **Recurse Down:** Search children.
Recursively search the left subtree and the right subtree for our target nodes.


3. **Evaluate Results:** Analyze split.
Look at what the children returned:

* If both the left and right searches returned a node, it means `p` is on one side and `q` is on the other. **The current node is the LCA.**
* If only one side returned a node, it means *both* targets are located down that specific branch, or one is the parent of the other. Pass that non-None result up.


---

### Python 3 Implementation

```python
# Definition for a binary tree node.
class TreeNode:
    def __init__(self, x):
        self.val = x
        self.left = None
        self.right = None

class Solution:
    def lowestCommonAncestor(self, root: TreeNode, p: TreeNode, q: TreeNode) -> TreeNode | None:
        # Base Case: if we hit the bottom, or if we find either p or q, 
        # we return the current node back up to the parent.
        if root is None or root == p or root == q:
            return root
        
        # Look for p and q in the left and right subtrees
        left_result = self.lowestCommonAncestor(root.left, p, q)
        right_result = self.lowestCommonAncestor(root.right, p, q)
        
        # If both left and right returned a non-None value, it means one target
        # is on the left and the other is on the right. This node is the LCA!
        if left_result and right_result:
            return root
        
        # If only one side returned a value, pass that value up. 
        # It means both p and q are down that side, or we found one of them.
        return left_result if left_result else right_result

```

### Tracing Example 2

Let's look at Example 2, where `p = 5` and `q = 4`.

```
       3 (Root)
      / \
     5   1
    / \
   6   2
      / \
     7   4

```

1. The code starts at `3`. It is not $p$ or $q$, so it calls left on `5`.
2. At node `5`, the base case triggers because `root == p`. Node `5` immediately returns **itself** back up to node `3`. **Crucially, it doesn't even need to explore its own children (`6` and `2`) to know it's an important endpoint.**
3. Node `3` now explores its right child, `1`. Node `1` explores its children, finds nothing, and returns `None`.
4. Back at the top level (node `3`):
* `left_result` = node `5`
* `right_result` = `None`


5. Since only one side is valid, node `3` returns `left_result`, which is **node `5**`. That is our correct LCA!

### Complexity Analysis

* **Time Complexity:** $O(N)$, where $N$ is the number of nodes in the tree. In the worst case, we might have to visit every node in the tree.
* **Space Complexity:** $O(H)$, where $H$ is the height of the tree, representing the memory used by the recursion stack. This is $O(\log N)$ for a balanced tree and $O(N)$ for a skewed tree.




Let’s look at this problem through a real-world analogy.

Imagine you and a coworker ($p$ and $q$) work in a multi-story corporate headquarters that is structured exactly like a binary tree—each manager has at most two people working directly under them.

You want to find your **Lowest Common Ancestor (LCA)**, which in this case means: **Who is the lowest-ranking manager in the company hierarchy who has authority over both of you?**

To find out, the CEO at the top of the tree sends a memo down the chain of command. Let's look at exactly how that message travels and how the decisions are made.

---

### 1. The Core Strategy: The Two-Way Signal

The recursive function acts like a manager asking their team two questions:

1. *"Is employee $p$ or $q$ working under you on the left side?"*
2. *"Is employee $p$ or $q$ working under you on the right side?"*

Depending on the answers they get back from their left and right assistants, a manager makes one of three logical choices:

#### Case A: The Split (You are the LCA)

If the left assistant says *"I found one of them!"* and the right assistant also says *"I found one of them!"*, then the manager realizes: *"Ah, one is on my left team, and the other is on my right team. **I am their lowest common boss!**"* They immediately send their own name up to their boss.

#### Case B: The Single File Line (One target is the boss of the other)

If one assistant returns a name, but the other assistant returns nothing (`None`), it means **both targets are down on that one side**.

Alternatively, it could mean the manager *is* one of the targets, and the other target is buried deep underneath them. (Like in Example 2, where node `5` is the boss of node `4`). The manager simply passes that valid result up the chain.

#### Case C: The Dead End

If both assistants return nothing (`None`), this entire branch is a dead end. The manager reports `None` to their boss.

### 3. Understanding the Base Case Shortcut

One detail that often confuses people is what happens when one node is a direct descendant of the other, like in Example 2 (`p = 5`, `q = 4`).

```
       3 
      / 
     5   <-- We stop here!
    / \
   6   2
        \
         4 

```

When the code hits node `5`, it matches `p`. It immediately stops and returns node `5` to the layer above.

You might wonder: *"Wait, we didn't even look down at node `2` or node `4`. How do we know node `4` is actually down there?"*

The problem guarantees that **both nodes exist in the tree**. If we are searching down a branch and encounter node `5` first, it means node `4` *must* be located somewhere inside node 5's subtrees. Because node `5` is higher up than node `4`, node `5` is automatically the lowest common ancestor of both. The code beautifully handles this without wasting time searching the lower levels!
