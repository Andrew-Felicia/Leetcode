This is a classic problem that boils down to **finding a cycle in a directed graph**.

Think of each course as a node, and each prerequisite [a, b] as a directed edge pointing from b to a (meaning b must be completed before starting a). If there is a cycle in this graph (e.g., Course 0 needs Course 1, and Course 1 needs Course 0), it's impossible to finish all the courses.

We can solve this efficiently using two primary approaches: **Breadth-First Search (BFS / Kahn's Algorithm)** or **Depth-First Search (DFS)**.

---

### Approach 1: Kahn's Algorithm (BFS via In-Degrees)

This approach mimics how a student actually picks courses. We track the "in-degree" of each course, which represents the number of prerequisites a course currently has.

## The Strategy

1. Build an adjacency list to represent the graph and an array to track the **in-degree** of each node.
2. Put all courses with an **in-degree of 0** (courses with no prerequisites) into a queue.
3. Pop a course from the queue, "take" it, and decrement the in-degree of all courses that depend on it.
4. If any dependent course's in-degree drops to 0, add it to the queue.
5. If the total number of courses we managed to "take" equals numCourses, return True. Otherwise, a cycle exists, so return False.

```python
from collections import deque, defaultdict

def canFinish(numCourses: int, prerequisites: list[list[int]]) -> bool:
    # Step 1: Build the graph and in-degree array
    graph = defaultdict(list)
    in_degree = [0] * numCourses
    
    for course, prereq in prerequisites:
        graph[prereq].append(course)
        in_degree[course] += 1
        
    # Step 2: Queue all courses with no prerequisites
    queue = deque([i for i in range(numCourses) if in_degree[i] == 0])
    
    visited_count = 0
    
    # Step 3: Process the queue
    while queue:
        current = queue.popleft()
        visited_count += 1
        
        for neighbor in graph[current]:
            in_degree[neighbor] -= 1
            if in_degree[neighbor] == 0:
                queue.append(neighbor)
                
    # Step 4: If we processed all courses, no cycle exists
    return visited_count == numCourses

```

### Approach 2: Depth-First Search (DFS Tracking)

Alternatively, you can use DFS to explore each course path completely, looking for a cycle.

## The Strategy

We need to track three states for each node to detect cycles cleanly:

* **0 (Unvisited):** We haven't looked at this course yet.
* **1 (Visiting):** We are currently exploring this course or its descendants in the *current* DFS path. If we hit a node in this state, we found a loop!
* **2 (Visited):** This course and all its dependencies have been fully checked and are safe.

```python
from collections import defaultdict

def canFinish(numCourses: int, prerequisites: list[list[int]]) -> bool:
    graph = defaultdict(list)
    for course, prereq in prerequisites:
        graph[prereq].append(course)
        
    # State array: 0 = unvisited, 1 = visiting, 2 = visited
    state = [0] * numCourses
    
    def has_cycle(node):
        if state[node] == 1:
            return True   # Found a cycle!
        if state[node] == 2:
            return False  # Already verified safe
            
        # Mark as visiting
        state[node] = 1
        
        for neighbor in graph[node]:
            if has_cycle(neighbor):
                return True
                
        # Mark as fully processed and safe
        state[node] = 2
        return False

    # Check every course (handles disconnected components)
    for i in range(numCourses):
        if state[i] == 0:
            if has_cycle(i):
                return False
                
    return True

```

### Complexity Analysis

Both algorithms are highly optimized and run well within the problem's constraints:

| Metric | Complexity | Why |
| --- | --- | --- |
| **Time Complexity** | $O(V + E)$ | We visit every course (vertex $V$) and every prerequisite (edge $E$) exactly once. |
| **Space Complexity** | $O(V + E)$ | Required to store the adjacency list graph representation and tracking structures. |


It is completely normal to find graph algorithms a bit tricky at first! Let’s strip away the fancy computer science terms and think about this like a real-world problem.

Imagine you are arriving at college on day one. You want to pick your classes, but the university has strict rules: you cannot take a class until you’ve finished all of its prerequisites.

The Breadth-First Search (BFS) approach—specifically an algorithm called **Kahn's Algorithm**—simulates exactly how you would graduate step-by-step.

---

### The Core Idea: The "In-Degree"

To make this work, we track a number for every single course called its **In-Degree**.

> **In-Degree** simply means: *"How many prerequisites do I still need to take before I am allowed to sign up for this specific course?"*

* If a class has an **In-Degree of 0**, it has no prerequisites left. You can take it **right now**.
* If a class has an **In-Degree of 2**, you must complete 2 other specific classes before you can touch it.

---

### Step-by-Step Walkthrough

Let's use a concrete example to see how the algorithm thinks.

* **Total Courses:** 4 (labeled 0, 1, 2, 3)
* **Prerequisites:**
* To take 1, you must take 0 first. [1, 0]
* To take 2, you must take 0 first. [2, 0]
* To take 3, you must take 1 and 2 first. [3, 1], [3, 2]



Here is how the algorithm processes this setup:

#### Step 1: Count the Prerequisites (In-Degrees)

First, we look at our list and count how many requirements each course has:

* Course 0: **0** prerequisites.
* Course 1: **1** prerequisite (needs 0).
* Course 2: **1** prerequisite (needs 0).
* Course 3: **2** prerequisites (needs 1 and 2).

#### Step 2: The "Available to Take" Queue

We create a waiting line (a **Queue**) and put in every course that has **0 prerequisites**. These are our starting classes.

* **Our Queue right now:** [ Course 0 ]
* **Courses completed counter:** 0

#### Step 3: Process the Queue (Taking Classes)

We start a loop that keeps running as long as there are classes in our queue.

**Round 1:**

1. We take **Course 0** out of the queue. We have now officially "completed" it! (Our completed counter becomes **1**).
2. Because we completed 0, any course that was waiting on 0 gets closer to being unlocked. We go to those courses and subtract 1 from their prerequisite count:
* Course 1's prerequisites drop from 1 down to **0**.
* Course 2's prerequisites drop from 1 down to **0**.


3. Look at that! Courses 1 and 2 now have **0 prerequisites left**. They are unlocked! We add them to our queue.

* **Our Queue right now:** [ Course 1, Course 2 ]

**Round 2:**

1. We take **Course 1** out of the queue. We complete it. (Completed counter becomes **2**).
2. Course 3 was waiting on 1. We reduce Course 3's prerequisite count by 1.
* Course 3's prerequisites drop from 2 down to **1**.


3. Is Course 3 ready yet? No, it still has 1 prerequisite left (it's still waiting on Course 2). So we don't add it to the queue yet.

* **Our Queue right now:** [ Course 2 ]

**Round 3:**

1. We take **Course 2** out of the queue. We complete it. (Completed counter becomes **3**).
2. Course 3 was also waiting on 2. We reduce Course 3's prerequisite count by 1.
* Course 3's prerequisites drop from 1 down to **0**.


3. Now Course 3 has 0 prerequisites left! It is unlocked. We add it to the queue.

* **Our Queue right now:** [ Course 3 ]

**Round 4:**

1. We take **Course 3** out of the queue. We complete it. (Completed counter becomes **4**).
2. Course 3 doesn't unlock anything else.

* **Our Queue right now:** [] (Empty!)

#### Step 4: The Final Check

The queue is empty, so our loop stops. We look at our counter: we successfully completed **4** courses. Because our completed count equals the total numCourses (4), it means we successfully finished everything without getting stuck! The answer is True.

---

### What happens if there is a cycle (a trap)?

What if Course 0 required Course 1, and Course 1 required Course 0? [[0, 1], [1, 0]]

1. Course 0 needs 1 prerequisite.
2. Course 1 needs 1 prerequisite.
3. We look for any course with **0 prerequisites** to start our queue... but there are none!
4. The queue starts empty, the loop never runs, and our completed counter stays at **0**.
5. At the end, 0 completed courses does not equal 2 total courses. The algorithm returns False.

Whenever there is a cycle, the courses involved in the loop will *never* see their prerequisite count drop to 0, so they get stuck in limbo and never enter the queue.

### The Code, Visualized Line-by-Line

Here is the exact code with comments matching our freshman enrollment analogy:

```python
from collections import deque, defaultdict

def canFinish(numCourses: int, prerequisites: list[list[int]]) -> bool:
    # 1. Setup the map of dependencies and the prerequisite counter
    graph = defaultdict(list)
    in_degree = [0] * numCourses
    
    # Fill up our map and counts
    for course, prereq in prerequisites:
        # prereq leads to course (e.g., 0 -> 1)
        graph[prereq].append(course) 
        # This course just got 1 more prerequisite added to its tally
        in_degree[course] += 1
        
    # 2. Find all freshman-ready classes (0 prerequisites) and put them in the queue
    queue = deque()
    for i in range(numCourses):
        if in_degree[i] == 0:
            queue.append(i)
            
    # Track how many classes we actually manage to graduate from
    courses_completed = 0
    
    # 3. Start attending classes
    while queue:
        # Take a class out of the queue and complete it
        current_course = queue.popleft()
        courses_completed += 1
        
        # Look at all the advanced classes that required the one we just finished
        for next_course in graph[current_course]:
            # They are now 1 prerequisite closer to being unlockable!
            in_degree[next_course] -= 1
            
            # If they have no prerequisites left, we can sign up for them!
            if in_degree[next_course] == 0:
                queue.append(next_course)
                
    # 4. Did we manage to finish every single class?
    return courses_completed == numCourses

```
