## 1. General solution idea

We are given ratings from `1` to `5`. We must rearrange all ratings so that:

```text
1. Adjacent ratings are different.
2. The resulting sequence is lexicographically smallest.
3. If impossible, output -1.
```

There are two main ideas:

1. Count how many times each rating appears.
2. Build the answer from left to right using a greedy algorithm.

At every position, try ratings in this order:

```text
1, 2, 3, 4, 5
```

Choose the first rating that:

- Is different from the previously chosen rating.
- Does not make arranging the remaining ratings impossible.

The second condition is the important part. Simply choosing the smallest different rating can lead to a dead end.

---

## 2. When is an arrangement possible?

Suppose we have:

```text
1 1 1 2 3
```

The three `1`s require other values to separate them:

```text
1 _ 1 _ 1
```

There are two gaps between the three `1`s, and the remaining values `2` and `3` can fill them:

```text
1 2 1 3 1
```

So this is possible.

Now consider:

```text
1 1 1 1 2 3
```

We would need:

```text
1 _ 1 _ 1 _ 1
```

There are three required gaps, but only two other values:

```text
2 and 3
```

Therefore, it is impossible.

### General condition

If there are `n` total values, the most frequent value can appear at most:

```text
ceil(n / 2)
```

Therefore:

```python
max(counts) <= (n + 1) // 2
```

must be true.

ASCII:

```text
Available positions for the most frequent value:

Position:  1  2  3  4  5  6  7
           X  _  X  _  X  _  X

Maximum X count = 4 = ceil(7 / 2)
```

---

## 3. Why choosing the smallest available rating is not enough

Consider:

```text
Ratings: 1, 2, 2, 2, 3
```

Counts:

```text
1 appears once
2 appears three times
3 appears once
```

A naive greedy algorithm chooses `1` first because it is the smallest:

```text
1 | 2 2 2 3
```

But the suffix cannot be arranged:

```text
2 _ 2 _ 2
```

It needs two separators, but only one `3` is available.

So choosing `1` first creates a dead end.

The correct answer begins with `2`:

```text
2 | 1 2 3 2
```

Final result:

```text
2 1 2 3 2
```

Therefore, before accepting a candidate, the program temporarily selects it and checks whether the remaining suffix can still be completed.

---

## 4. Understanding the suffix feasibility check

Suppose we just selected rating `X`:

```text
... X | _ _ _ _ _
        remaining suffix
```

Let the suffix length be `m`.

The first suffix value cannot be `X`, because it would be adjacent to the selected `X`.

### Positions available for `X`

For a suffix of length five:

```text
Previous:       X

Suffix index:   1   2   3   4   5
Can place X:    no  yes no  yes no
                    X       X
```

`X` can appear at most:

```text
floor(m / 2)
```

times.

For `m = 5`:

```text
floor(5 / 2) = 2
```

That is why the code uses:

```python
same_limit = suffix_length // 2
```

### Positions available for another rating

Another rating, such as `Y`, may appear immediately after `X`:

```text
Previous:       X

Suffix index:   1   2   3   4   5
Can place Y:    yes no  yes no  yes
                Y       Y       Y
```

It can appear at most:

```text
ceil(m / 2)
```

times.

For `m = 5`:

```text
ceil(5 / 2) = 3
```

That is why the code uses:

```python
other_limit = (suffix_length + 1) // 2
```

### Complete condition after choosing rating `X`

```text
Remaining copies of X:
    must be <= floor(m / 2)

Remaining copies of every other rating:
    must be <= ceil(m / 2)
```

If these conditions hold, the suffix can be completed.

---

## 5. Greedy construction diagram

At every position:

```text
                  Try rating 1
                       |
              +--------+--------+
              |                 |
        Same as previous?     Available?
              |                 |
             skip             continue
                                |
                                v
                     Temporarily remove it
                                |
                                v
                      Can suffix be built?
                          /           \
                        yes            no
                        /               \
                Keep rating       Put rating back
                Add to answer     Try next rating
```

Because ratings are tried in increasing order:

```text
1 → 2 → 3 → 4 → 5
```

the first feasible rating produces the lexicographically smallest answer.

import sys

## Construction function

```python
def construct_smallest(counts):
```

Constructs the lexicographically smallest valid arrangement.

`counts` contains five elements:

```text
counts[0] = number of rating 1
counts[1] = number of rating 2
counts[2] = number of rating 3
counts[3] = number of rating 4
counts[4] = number of rating 5
```

For example:

```text
Ratings: 1 1 2 3 3 3
```

produce:

```python
counts = [2, 1, 3, 0, 0]
```

---

```python
counts = list(counts)
```

Creates a copy of the counts.

The algorithm modifies `counts` while constructing the answer. Copying prevents it from changing the caller’s original list.

---

```python
remaining = sum(counts)
```

Calculates how many ratings have not yet been placed.

For:

```python
counts = [2, 1, 3, 0, 0]
```

we get:

```text
remaining = 2 + 1 + 3 = 6
```

---

## Initial impossibility check

```python
if remaining and max(counts) > (remaining + 1) // 2:
    return None
```

Checks whether one rating appears too many times.

The maximum allowed count is:

```text
ceil(remaining / 2)
```

which is calculated using:

```python
(remaining + 1) // 2
```

Example:

```text
remaining = 5
maximum allowed = (5 + 1) // 2 = 3
```

If one rating appears four times, no valid arrangement exists.

```python
return None
```

means “impossible.”

The `remaining and ...` part prevents calling `max()` on an empty list/state, although the problem normally has at least one rating.

---

## Prepare the answer

```python
answer = []
```

Creates a list for the resulting sequence.

Strings will eventually be stored here:

```python
["1", "2", "1", "3"]
```

---

```python
previous = -1
```

Stores the previously selected rating.

Internally, ratings use indexes:

```text
index 0 = rating 1
index 1 = rating 2
...
index 4 = rating 5
```

`-1` means that no rating has been selected yet.

---

## Construct every position

```python
while remaining:
```

Continues until all ratings have been placed.

---

```python
suffix_length = remaining - 1
```

We are about to choose one rating.

After choosing it, the number of ratings left will be:

```text
remaining - 1
```

That is the suffix length.

---

```python
same_limit = suffix_length // 2
```

Calculates how many more copies of the chosen rating may remain.

Because the suffix cannot begin with the same rating, it can occupy at most:

```text
floor(suffix_length / 2)
```

positions.

---

```python
other_limit = (suffix_length + 1) // 2
```

Calculates how many copies of any other rating may remain.

Another rating may occupy at most:

```text
ceil(suffix_length / 2)
```

positions.

---

```python
chosen = -1
```

Means that no valid rating has been chosen for this position yet.

---

## Try ratings from smallest to largest

```python
for rating in range(5):
```

Tries internal rating indexes:

```text
0, 1, 2, 3, 4
```

which correspond to actual ratings:

```text
1, 2, 3, 4, 5
```

Trying them in this order guarantees lexicographic minimality.

---

```python
if rating == previous or counts[rating] == 0:
    continue
```

Rejects a rating when:

1. It is equal to the previous rating.
2. No copies of it remain.

Example:

```text
previous = rating 2
candidate = rating 2
```

This would create:

```text
... 2 2
```

so it must be skipped.

---

## Temporarily choose the rating

```python
counts[rating] -= 1
```

Pretends to place this rating in the answer.

For example:

```python
counts = [2, 3, 1, 0, 0]
```

If rating `2` is tested:

```python
counts[1] -= 1
```

resulting in:

```python
counts = [2, 2, 1, 0, 0]
```

---

## Check copies of the chosen rating

```python
feasible = counts[rating] <= same_limit
```

Checks whether the remaining copies of this same rating can fit into the suffix.

Suppose the candidate is `2`:

```text
... 2 | suffix
```

The suffix cannot begin with `2`, so remaining `2`s have only:

```text
floor(suffix_length / 2)
```

available positions.

If there are too many, this candidate is invalid.

---

## Check every other rating

```python
if feasible:
```

Only continue checking if the chosen rating itself passed.

---

```python
for other in range(5):
```

Examines all five rating types.

---

```python
if other != rating and counts[other] > other_limit:
```

For every rating other than the selected one, checks whether its remaining count exceeds:

```text
ceil(suffix_length / 2)
```

---

```python
feasible = False
break
```

Marks the candidate as invalid and stops checking.

---

## Accept a feasible rating

```python
if feasible:
    chosen = rating
    break
```

If the suffix can still be completed:

1. Save this rating as the selected rating.
2. Stop trying larger ratings.

Because candidates are tested from smallest to largest, this is the smallest feasible choice.

Notice that the earlier decrement is not undone. That copy has now officially been used.

---

## Undo a rejected choice

```python
counts[rating] += 1
```

If the candidate was not feasible, restore the temporarily removed copy.

Then the loop tries the next rating.

ASCII:

```text
Try rating
    |
remove one
    |
suffix impossible?
    |
   yes
    |
put it back
    |
try next rating
```

---

## No candidate worked

```python
if chosen == -1:
    return None
```

If none of ratings `1–5` can be placed here, a valid sequence is impossible.

Normally, the feasibility invariant prevents this after construction begins, but this remains a safety check.

---

## Add the chosen rating

```python
answer.append(str(chosen + 1))
```

Internal indexes are zero-based:

```text
chosen = 0 means rating 1
chosen = 1 means rating 2
...
```

Therefore:

```python
chosen + 1
```

converts the index back into the actual rating.

It is converted to a string so output can later be generated using `" ".join(...)`.

---

```python
previous = chosen
```

Records the selected rating so the next position cannot use the same one.

---

```python
remaining -= 1
```

One more rating has been placed, so decrease the remaining total.

---

```python
return answer
```

After all ratings have been placed, return the constructed sequence.

Example:

```python
["1", "2", "1", "3", "2"]
```

## 8. Complete example

Input:

```text
5
1 2 2 2 3
```

Counts:

```text
Rating:  1  2  3  4  5
Count:   1  3  1  0  0
```

### Position 1

Try `1`:

```text
1 | 2 2 2 3
```

Suffix length is four.

A different rating may appear at most:

```text
ceil(4 / 2) = 2
```

But three copies of `2` remain:

```text
3 > 2
```

So `1` is rejected.

Try `2`:

```text
2 | 1 2 2 3
```

The same rating `2` may appear at most:

```text
floor(4 / 2) = 2
```

Exactly two copies remain, so this is feasible.

Choose `2`.

### Remaining construction

```text
2
2 1
2 1 2
2 1 2 3
2 1 2 3 2
```

Final answer:

```text
2 1 2 3 2
```

## 9. Complexity

At every output position:

- At most five candidate ratings are tried.
- At most five counts are checked.

That is at most `25` operations per position, which is constant.

Therefore:

```text
Time:  O(n)
Space: O(n)
```

The algorithmic techniques are:

- Frequency counting
- Lexicographic greedy construction
- Feasibility checking
- Separator/pigeonhole principle
- Maintaining a valid-suffix invariant
