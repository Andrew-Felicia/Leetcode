## Working out the model

Two readings are possible for "leaving point `i`, may carry no more than `A_i`":
1. **Total cap**: carried amount when leaving `i` must be ≤ `A_i` (absolute ceiling).
2. **Pickup cap**: the amount she *adds* at `i` is ≤ `A_i`, but it stacks on top of whatever she already carries (total isn't capped by `A_i`).

I traced the sample by hand under both models. Under model (1), only the path `1→2→5` is usable at all (every path through node 3/4 gets blocked because carrying enough to cross edge `1→4` or `3→4` would exceed the node's own cap), giving `5` — but the expected answer is `4`. Under model (2), the path `1→3→4→5` becomes viable: pick up `2` at node 1 (carry=2, satisfies edge `1→3` needing 2), pick up `2` more at node 3 (carry=4, satisfies edge `3→4` needing 4), pick up `0` at node 4 (carry stays 4, satisfies edge `4→5` needing 3) → arrives with **4**. That matches.

So the correct model: carry is cumulative and non-decreasing along the path; at each node you may add between `0` and `A_i` more (not an absolute cap on the total).

## The DP

Since every edge goes from a lower index to a higher index (`U_j < V_j`), the graph is a DAG where node index order **is** a valid topological order. So:

- `d[v]` = minimum possible carry when arriving at `v`
- `d[1] = 0`
- For edge `(u, v, w)`: usable iff `d[u] + A[u] >= w` (i.e., even maxing out pickup at `u` is enough to meet the edge's requirement). If usable, the cheapest sufficient carry to leave `u` is `max(d[u], w)`, so `d[v] = min(d[v], max(d[u], w))`.

## Explanation

**The graph is a DAG by construction.** Since every edge satisfies `U_j < V_j`, processing nodes in plain index order `1, 2, ..., n` is automatically a valid topological order — no separate topological sort step needed.

**`d[u]` represents the minimum possible carry when arriving at node `u`.** We initialize `d[1] = 0` (start with nothing) and everything else as infinity (unreached).

**For each node `u`, once `d[u]` is finalized** (guaranteed by the processing order, since all edges into `u` come from smaller indices which were already processed), we look at every outgoing edge `(u, v, w)`:
- The most she could possibly carry leaving `u` is `d[u] + A[u]` — her current carry plus everything she could pick up there. If even that's not enough to meet the edge's requirement `w`, this edge is simply unusable from this arrival state (`w > cap` → skip).
- If it is usable, the *cheapest* way to satisfy it is to pick up just enough to reach `max(d[u], w)` — no more, no less — since carrying more than necessary only makes future constraints harder to satisfy for no benefit.
- That value becomes a candidate for `d[v]`, and we keep the smallest candidate seen from any incoming edge.
