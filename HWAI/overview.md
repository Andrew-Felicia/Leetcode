# 从零理解机器学习、深度学习与大模型：全景学习地图

这份笔记把你目前学习过的内容串成一条主线：

```text
数据 → 特征 → 模型 → 前向预测 → 损失 → 反向传播 → 参数更新
     → 验证评估 → 部署推理 → 性能/显存优化
```

目标不是一次记住全部术语，而是先知道每个概念在整条流程中的位置。

---

## 1. 机器学习、深度学习和大模型分别是什么？

### 1.1 机器学习（Machine Learning）

机器学习的目标是：从数据中找到规律，而不是由人手工写死所有规则。

例子：根据房屋面积、位置、房龄预测房价。

```text
输入特征 X → 模型 → 预测结果 y_hat
真实答案 y → 用于告诉模型预测得好不好
```

常见机器学习任务：

| 任务 | 输入 | 输出 | 例子 |
|---|---|---|---|
| 回归 | 特征 | 连续数值 | 预测降雨量、房价 |
| 二分类 | 特征 | 0 或 1 | 垃圾邮件、是否违约 |
| 多分类 | 特征 | 多个类别之一 | 图片是猫/狗/鸟 |
| 聚类 | 无标签特征 | 若干组 | 用户分群、终端型号分群 |
| 检索 | 查询和文档 | 相似文档 | RAG 找知识库内容 |

### 1.2 深度学习（Deep Learning）

深度学习是机器学习的一部分。它使用多层神经网络，自动学习更复杂的特征表示。

```text
原始输入
  ↓
第一层：较简单的模式
  ↓
中间层：组合成更复杂的模式
  ↓
输出层：预测类别或数值
```

图像中可能是：

```text
像素 → 边缘 → 纹理 → 眼睛/耳朵 → 猫
```

### 1.3 大模型（LLM）

大语言模型通常是参数量很大的 Transformer。它的核心训练任务可简单理解为：

```text
根据前面的 token，预测下一个 token
```

例如：

```text
“今天天气很” → 预测下一个 token 可能是 “好”
```

经过海量文本预训练后，它学习到语言、知识、代码和一定的推理模式。

## 2. CPU、GPU、NPU：它们分别做什么？

```text
                 一台训练/推理机器

CPU ── 调度、数据加载、控制逻辑、通用计算
 │
 ├── GPU ── 大规模并行矩阵乘法，常用于深度学习训练/推理
 │
 └── NPU ── 针对神经网络张量运算优化的加速器，常用于端侧或 AI 服务器
```

### 2.1 CPU

CPU 的特点：

```text
核心数量相对少
单核能力强
擅长复杂控制逻辑、条件判断、数据预处理、操作系统任务
```

在训练中，CPU 常负责：

```text
读取数据集
数据清洗与增强
把 batch 送到 GPU/NPU
日志、调度和保存 checkpoint
```

### 2.2 GPU

GPU 有大量可并行执行的计算单元，擅长相同类型的大量计算：

```text
矩阵乘法
卷积
注意力计算
向量运算
```

神经网络中的很多核心运算都可以写成矩阵乘法：

```text
Y = XW
```

所以 GPU 很适合训练和推理。

### 2.3 NPU

NPU（Neural Processing Unit）是为 AI 张量计算优化的硬件。它常强调：

```text
矩阵乘法吞吐
低精度计算，例如 FP16、INT8、INT4
更低能耗
端侧/边缘设备部署
```

部署到 NPU 时并不是“模型一定自动跑在 NPU”。若日志出现：

```text
unsupported op
fallback
compile fail
```

可能代表某些算子不支持、回退到 CPU，或编译失败。

### 2.4 简单对比

| 硬件 | 更擅长什么 | 常见 AI 工作 |
|---|---|---|
| CPU | 通用逻辑、串行控制 | 数据加载、调度、预处理 |
| GPU | 大规模并行浮点/张量计算 | 训练、批量推理 |
| NPU | 神经网络专用张量计算、能效 | 部署推理、AI 加速 |

## 3. 数据集：模型到底从什么学习？

### 3.1 样本、特征、标签

一个监督学习样本通常是：

```text
(X, y)
```

其中：

```text
X：特征，例如 [面积、房龄、位置分数]
y：标签/真实答案，例如 房价
```

分类例子：

```text
输入：邮件文本特征
标签：垃圾邮件 = 1，正常邮件 = 0
```

### 3.2 训练集、验证集、测试集

```text
完整数据集
├── 训练集 Train：用于更新模型参数
├── 验证集 Validation：用于选择模型、调超参数、早停
└── 测试集 Test：最后一次客观评估，不应参与调参
```

常见示例比例：

```text
70% 训练
15% 验证
15% 测试
```

这不是硬规则。数据少时可做 K 折交叉验证；时间序列应按时间切分，不能让未来数据泄露到过去。

### 3.3 为什么不能数据泄露？

错误例子：

```text
训练集里已经有测试题或它的近似改写
```

模型可能只是记住题目，测试分数虚高，却不代表真的会泛化。

近似泄露可以用：

```text
语义向量检索
MinHash 近似去重
重复/相似文本检测
```

### 3.4 类别不平衡

假设：

```text
正类：1%
负类：99%
```

一个永远预测负类的模型也有 `99%` 准确率，但完全找不到正类。

因此可以使用：

```text
重采样
类别权重
F1、Recall、Precision、AUC-PR
```

不要只看 Accuracy。

## 4. 特征工程与数据预处理

模型只能读取数字，因此输入往往需要变换。

### 4.1 标准化

```text
x_standard = (x - 均值) / 标准差
```

标准化后特征通常接近：

```text
均值 0
方差 1
```

用途：

```text
PCA
KNN
K-means
梯度下降模型
```

因为欧氏距离和方差都会受数值尺度影响。

### 4.2 One-hot / 存在编码

类别特征可转换为数值。

```text
颜色 = 红/绿/蓝

红 → [1, 0, 0]
绿 → [0, 1, 0]
蓝 → [0, 0, 1]
```

你做过的 A–G 字母题是“存在编码”：

```text
ABC → [1, 1, 1, 0, 0, 0, 0]
AAA → [1, 0, 0, 0, 0, 0, 0]
```

它不关心出现次数，只关心是否出现。

### 4.3 Embedding

Embedding 是稠密、可学习的向量表示。

```text
“猫” → [0.2, 0.7, -0.1, ...]
“狗” → [0.3, 0.6, -0.2, ...]
```

语义接近的词/文本，向量通常也更接近。

它用于：

```text
文本分类
相似度计算
语义检索
RAG
跨语言检索
```

## 5. 三类最常见学习范式

```text
监督学习：有答案
无监督学习：没有答案，只找结构
强化学习：根据奖励学习决策
```

### 5.1 监督学习

训练数据包含 `X` 和 `y`。

```text
输入邮件 → 标签：垃圾/正常
输入房屋 → 标签：房价
```

常见算法：

```text
线性回归
逻辑回归
决策树、随机森林、XGBoost
神经网络
```

### 5.2 无监督学习

没有人工标签，目标是发现数据结构。

```text
用户分群
终端型号聚类
异常检测
降维可视化
```

常见算法：

```text
K-means
层次聚类 HAC
DBSCAN
PCA
t-SNE（更偏可视化）
```

### 5.3 强化学习

模型与环境交互，根据奖励学习。

```text
状态 → 动作 → 奖励 → 改进策略
```

例子：机器人控制、游戏、部分 LLM 对齐训练。

## 6. KNN：先找邻居，再投票

KNN（K-Nearest Neighbors）是监督学习分类算法。

```text
新样本
  ↓
计算它与所有训练样本的距离
  ↓
取最近的 K 个邻居
  ↓
多数投票决定类别
```

ASCII 例子：

```text
类别 0：o o o
类别 1：x x x

          ?  新样本

若 ? 最近的 5 个样本中：
0 类有 4 个，1 类有 1 个
→ 预测为 0 类
```

常用欧氏距离：

```text
d(x, y) = sqrt(Σ(xi - yi)²)
```

### KNN 的关键点

```text
必须先标准化：不同尺度会扭曲距离
K 太小：容易受噪声影响
K 太大：可能混入其他类别
高维数据：近邻关系可能不可靠
数据很大：逐个算距离很慢
```

KNN 几乎没有显式训练过程，因此也被称为“懒惰学习”。

## 7. K-means：不断分配和更新中心

K-means 是无监督聚类算法。它希望把数据分成 `K` 个簇。

```text
初始化 K 个中心
       ↓
每个样本分给最近中心
       ↓
每个簇重新计算平均中心
       ↓
重复，直到中心基本不动
```

ASCII 示例：

```text
开始：

o o o       x x x
    C1          C2

分配：左边样本归 C1，右边样本归 C2

更新：C1、C2 移到各自簇样本的平均位置
```

K-means 的目标可以理解为：让簇内样本到各自中心的平方距离总和尽量小。

### K-means 的注意点

```text
需要事先指定 K
初始中心会影响结果
通常使用欧氏距离，因此也需要标准化
对异常值敏感
每轮必须清空 clusters，再重新分配样本
```

你做过 YOLO Anchor 的 K-means：它使用的是框之间的 IoU 距离，而不是普通欧氏距离。

## 8. 常见传统机器学习模型

| 方法 | 适合什么 | 核心想法 |
|---|---|---|
| 线性回归 | 连续数值预测 | `y = wᵀx + b` |
| 逻辑回归 | 二分类 | 线性分数后接 Sigmoid |
| 决策树 | 规则型分类/回归 | 不断按特征阈值分裂 |
| 随机森林 | 表格数据 | 多棵树投票/平均 |
| XGBoost/GBDT | 表格数据 | 逐步添加树修正错误 |

| K-means | 无标签聚类 | 分配样本和更新中心 |

实战中，表格数据常先尝试：

```text
线性/逻辑回归 → 树模型 → XGBoost/LightGBM → 神经网络
```

## 9. 神经网络从零训练：完整主线

### 9.1 一个神经元

一个神经元的核心是：

```text
z = wᵀx + b
output = activation(z)
```

其中：

```text
x：输入特征
w：权重
b：偏置
z：线性打分
activation：激活函数
```

例子：

```text
w = [1, 2]
x = [3, 4]
b = 1

z = 1×3 + 2×4 + 1 = 12
```

### 9.2 MLP：多个神经元和多层

MLP（多层感知机）可以写成：

```text
输入 X
  ↓
隐藏层：H = activation(XW1 + b1)
  ↓
输出层：Y_hat = output_activation(HW2 + b2)
```

ASCII：

```text
输入层              隐藏层               输出层
[x1] ───────┐       [h1] ───────┐
[x2] ───────┼────→  [h2] ───────┼────→ [预测]
[x3] ───────┘       [h3] ───────┘
```

### 9.3 激活函数怎么选？

| 场景 | 常见输出/隐藏层激活 |
|---|---|
| 隐藏层 | ReLU、Leaky ReLU、GELU、Swish |
| 二分类输出 | Sigmoid |
| 多分类输出 | Softmax |
| 一般连续值回归输出 | 不加激活函数（线性输出） |

常见函数：

```text
ReLU(x) = max(0, x)
Sigmoid(x) = 1 / (1 + e^(-x))
Tanh(x)：范围 (-1, 1)
```

为什么隐藏层经常使用 ReLU/GELU，而不是 Sigmoid？

```text
Sigmoid 在很大正/负数处导数接近 0，容易梯度消失
ReLU 在正半轴导数为 1，梯度传播通常更容易
GELU/Swish 是平滑的现代常用激活
```

### 9.4 前向传播（Forward Pass）

前向传播就是“输入经过当前参数，得到预测”。

```text
x → 网络 → y_hat
```

分类例子：

```text
输入邮件特征 → 模型输出 p=0.82
→ 模型认为它是垃圾邮件的概率约为 82%
```

### 9.5 损失函数（Loss）

损失用于衡量预测和真实答案之间的差距。

| 任务 | 常见损失 |
|---|---|
| 回归 | MSE、MAE、Huber Loss |
| 二分类 | Binary Cross-Entropy（BCE） |
| 多分类 | Cross-Entropy |

二分类中：

```text
y = 真实标签
p = 模型预测为正类的概率

BCE = -[y log(p) + (1-y)log(1-p)]
```

Sigmoid + BCE 的一个重要优点：

```text
对线性打分 z 的梯度 = p - y
```

它很适合逻辑回归和二分类神经网络。

### 9.6 反向传播（Backpropagation）

反向传播做的事：计算“每个参数应朝哪个方向改，才能让损失降低”。

```text
前向：x → y_hat → loss
反向：loss → 每层梯度 → 每个参数的梯度
```

它使用链式法则：

```text
如果 loss 依赖于 a，a 又依赖于 w：
d(loss)/dw = d(loss)/da × da/dw
```

反向传播能高效得到所有参数的梯度，而不是每次只测试一个参数。

### 9.7 梯度下降与优化器

最基础更新规则：

```text
w_new = w_old - learning_rate × gradient
```

含义：

```text
gradient：损失增大最快的方向
-gradient：损失下降最快的局部方向
learning_rate：每次走多大一步
```

常见优化器：

| 优化器 | 特点 |
|---|---|
| SGD | 最基本；可配 Momentum |
| Adam | 自适应学习率，常用 |
| AdamW | Adam + 更合理的 Weight Decay；Transformer 训练常见 |

常见学习率策略：

```text
Warmup：训练初期从小学习率逐步升高
Step Decay：每隔若干轮降低学习率
Cosine Annealing：余弦形式逐渐降低学习率
指数衰减：按固定比例下降
```

### 9.8 Epoch、Batch、Batch Size

```text
一个样本：1 条数据
一个 batch：一次送入模型的一小批样本
一个 epoch：训练集全部样本训练一遍
```

例子：

```text
训练集 1,000 条
batch size = 100
→ 一个 epoch 有 10 次参数更新
```

你做过的逻辑回归题使用：

```text
batch size = 1
```

即每读到一个样本就立刻更新一次参数，称为 SGD 风格更新。

## 10. 怎样避免过拟合？

过拟合：模型把训练集细节甚至噪声记住了，但遇到新数据效果差。

```text
训练集分数很高
验证集/测试集分数明显更低
```

常见办法：

```text
更多、更干净、更有代表性的数据
数据增强
L2 正则化 / Weight Decay
Dropout
Early Stopping
减小模型复杂度
合理数据切分，避免泄露
```

L2 正则化：

```text
loss = 原始损失 + λΣw²
```

它抑制过大的权重，使模型通常更平滑。

## 11. 如何评估模型？

### 11.1 分类：混淆矩阵

```text
                 实际正类   实际负类
预测正类            TP        FP
预测负类            FN        TN
```

常见指标：

```text
Precision = TP / (TP + FP)
Recall    = TP / (TP + FN)
F1        = 2PR / (P + R)
Accuracy  = (TP + TN) / 总数
```

直觉：

```text
Precision：模型说“是”的时候，有多可信？
Recall：所有真正的正类中，模型找回了多少？
F1：Precision 与 Recall 的平衡
```

### 11.2 回归

```text
MAE  = 平均绝对误差
MSE  = 平均平方误差
RMSE = sqrt(MSE)
```

极端异常值通常对 RMSE 更敏感，因为误差会平方。

## 12. 深度学习中最常见的网络结构

| 网络 | 主要场景 | 关键想法 |
|---|---|---|
| MLP | 表格数据、简单特征 | 多层全连接网络 |
| CNN | 图像、局部空间模式 | 卷积核扫描局部区域 |
| RNN | 序列数据 | 隐藏状态传递记忆 |
| LSTM/GRU | 长序列 | 门控缓解梯度问题 |
| Transformer | 文本、多模态、LLM | 自注意力建模全局依赖 |
| ViT | 图像 | 图像切成 Patch 后用 Transformer |

### 12.1 CNN

卷积可理解为一个小窗口在图像上滑动：

```text
输入图像局部区域 × 卷积核
        ↓
逐元素相乘并求和
        ↓
输出一个特征值
```

分组卷积把通道和卷积核分组；深度卷积可以进一步减少计算。

### 12.2 RNN 与 LSTM

RNN：

```text
h_t = f(Wx_t + Uh_(t-1))
```

问题：长序列中可能梯度消失或爆炸。

LSTM 使用门控：

```text
遗忘门：忘掉什么
输入门：写入什么
输出门：输出什么
```

### 12.3 Transformer 与注意力

自注意力：

```text
Q = XWq
K = XWk
V = XWv

Attention(Q,K,V) = softmax(QKᵀ / sqrt(d))V
```

直觉：

```text
Q：我在找什么
K：我能与什么匹配
V：我真正提供什么信息
```

多头注意力让模型从多个子空间观察关系。

复杂度中的关键项：

```text
注意力矩阵大小：n×n
注意力相关计算量：O(n²d)
```

这也是长上下文昂贵的主要原因。

## 13. 大模型训练流程

```text
1. 收集和清洗大规模数据
2. Tokenization：把文本变为 token ID
3. 预训练：预测下一个 token
4. SFT：按 instruction → output 学习指令跟随
5. 偏好/对齐训练：提高有帮助性与安全性
6. 评测：能力、安全、幻觉、延迟、成本
7. 部署推理：批处理、KV Cache、量化、服务调度
```

### 13.1 预训练

```text
“人工智能正在改变” → 预测下一个 token
```

通常数据量巨大，训练目标是语言建模。

### 13.2 SFT

SFT 数据最常见形式：

```json
{
  "instruction": "解释什么是 K-means",
  "output": "K-means 是一种无监督聚类算法……"
}
```

### 13.3 RAG

RAG 不一定把新知识训练进参数，而是：

```text
问题
 ↓
Embedding 检索知识库
 ↓
相关文档片段
 ↓
LLM 根据证据回答
```

常见改进：

```text
按标题/段落合理切 Chunk，并保留适量重叠
向量检索后加入 Rerank
只把高质量证据送给模型
要求回答带引用；没有证据则拒答或说明不知道
```

## 14. 多卡训练和显存问题

### 14.1 数据并行

```text
一个 batch
 ├── GPU/NPU 0：处理样本的一部分
 ├── GPU/NPU 1：处理样本的一部分
 ├── GPU/NPU 2：处理样本的一部分
 └── GPU/NPU 3：处理样本的一部分

每张卡有一份模型
各自计算梯度
再同步/聚合梯度
```

目标是提高吞吐量。

### 14.2 训练显存主要花在哪里？

```text
模型参数
优化器状态
梯度
中间激活值
```

Activation Checkpointing / 重计算主要减少：

```text
中间激活值显存
```

### 14.3 训练显存优化手段

```text
混合精度：FP32 → FP16/BF16
Activation Checkpointing：少存激活，反向时重算
梯度累积：小显存模拟较大 batch
ZeRO/FSDP：分片存储参数、梯度、优化器状态
```

## 15. 大模型推理：Prefill、Decode、KV Cache

### 15.1 两个阶段

```text
用户 Prompt：”解释 KNN“

Prefill：一次处理整个 Prompt
Decode：一次生成一个新 token，直到结束
```

```text
Prompt tokens ── Prefill ──→ KV Cache
                                │
                                └── Decode token 1 → token 2 → token 3 ...
```

### 15.2 KV Cache

每层注意力都需要历史 token 的 Key 和 Value。

KV Cache 保存这些历史结果，避免每生成一个 token 都重算整段历史。

但它会占用显存，大致随以下因素增长：

```text
层数 × token 数 × 注意力头/隐藏维度 × 数值位宽
```

### 15.3 推理优化手段

```text
连续批处理 Continuous Batching
PagedAttention / 分页 KV Cache
Prefix Cache / 前缀缓存
滑动窗口注意力
量化：INT8、INT4、FP8 等
投机采样 Speculative Decoding
张量并行、流水线并行、专家并行
```

滑动窗口注意力：

```text
只保留最近 W 个 token 的 KV
```

它限制了可关注的历史范围，但降低了长序列 KV Cache 的增长压力。

## 16. 量化、剪枝与端侧部署

### 16.1 量化

量化把高位宽数值转换为低位宽表示：

```text
FP32 → INT8 / INT4
```

优点：

```text
模型更小
显存更少
内存带宽压力更低
某些硬件上推理更快
```

代价：

```text
存在量化误差
长文本/多层计算中误差可能累积
不是一定提升精度
```

### 16.2 剪枝

剪枝删除“不重要”的参数或结构。

结构化剪枝例子：

```text
删除权重矩阵的一整行
→ 对应删除一个输入特征
```

你练过按每行 L1 范数剪枝：

```text
L1(row) = Σ |weight|
```

L1 小的行可能被认为较不重要。

## 17. vLLM 和 SGLang：它们不是训练模型的框架

一句话：

```text
PyTorch/训练代码：负责训练模型
vLLM、SGLang：主要负责把训练好的大模型高效地“提供推理服务”
```

### 17.1 vLLM

vLLM 是高吞吐 LLM 推理/服务引擎。它的代表性思路是：

```text
PagedAttention：把 KV Cache 像操作系统分页一样按块管理
Continuous Batching：请求完成/加入不必等待整个固定 batch 结束
```

这样可以缓解 KV Cache 碎片，提高显存利用和服务吞吐。vLLM 官方资料将 PagedAttention、连续批处理和高 GPU 利用率作为核心能力。 [vLLM 官方网站](https://vllm.ai/)

### 17.2 SGLang

SGLang 是面向高性能 LLM/多模态推理服务的运行时，也提供了更适合结构化生成程序的接口。

你可以重点记住：

```text
RadixAttention：利用共享前缀复用 KV Cache
Prefix Caching：多个请求有相同前缀时，减少重复计算
Structured Generation：更方便做受控/结构化输出
Continuous Batching：持续动态组 batch
```

SGLang 官方文档将 RadixAttention、前缀缓存、多 GPU 并行与高吞吐低延迟推理列为核心能力。 [SGLang 官方文档](https://sgl-project.github.io/)

### 17.3 它们的共同点和区别

| 项目 | vLLM | SGLang |
|---|---|---|
| 主要用途 | 高吞吐 LLM 推理服务 | 高性能推理服务与结构化生成程序 |
| 重点记忆 | PagedAttention、连续批处理 | RadixAttention、前缀复用、结构化生成 |
| 是否训练模型 | 否，主要是服务训练好的模型 | 否，主要是服务训练好的模型 |
| 是否处理 KV Cache | 是 | 是 |

初学时不必背所有工程细节。先记住它们都在解决：

```text
如何让更多用户并发使用模型，
同时减少 KV Cache 浪费、提高吞吐、降低延迟。
```

## 19. 最后的一张总流程图

```text
                    ┌────────────────────┐
                    │ 收集、清洗、标注数据 │
                    └─────────┬──────────┘
                              ↓
                    ┌────────────────────┐
                    │ 特征处理/Embedding  │
                    │ 标准化、切分数据集   │
                    └─────────┬──────────┘
                              ↓
                    ┌────────────────────┐
                    │ 选择模型             │
                    │ KNN/树/MLP/Transformer│
                    └─────────┬──────────┘
                              ↓
                    ┌────────────────────┐
                    │ 前向传播：得到预测   │
                    └─────────┬──────────┘
                              ↓
                    ┌────────────────────┐
                    │ Loss：衡量预测误差   │
                    └─────────┬──────────┘
                              ↓
                    ┌────────────────────┐
                    │ Backprop：计算梯度   │
                    └─────────┬──────────┘
                              ↓
                    ┌────────────────────┐
                    │ Optimizer：更新参数  │
                    │ SGD / Adam / AdamW  │
                    └─────────┬──────────┘
                              ↓
                    ┌────────────────────┐
                    │ 验证与评估           │
                    │ F1、RMSE、AUC 等     │
                    └─────────┬──────────┘
                              ↓
                    ┌────────────────────┐
                    │ 部署推理             │
                    │ GPU/NPU、KV Cache    │
                    │ 量化、vLLM、SGLang   │
                    └────────────────────┘
```

最重要的主线只有一句：

```text
模型先根据当前参数做预测；
再根据预测与真实答案的差距计算损失；
然后用梯度一点点修改参数，让下一次预测更好。
```
