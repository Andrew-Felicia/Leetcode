常见的数据归一化/标准化方式你怎么选？不同方案的差异点与适用场景讲清楚。



我的选择原则可以先压缩成一句话：

> **默认用 Z-score 标准化；有严重异常值用 RobustScaler；有明确上下界或神经网络输入用 Min-Max；稀疏数据用 MaxAbs；比较方向而不是长度时用 L2 单位化；强偏态先做对数或幂变换，再标准化。**

## 先区分两个概念

日常表达中两者经常混用，但严格来说：

- **标准化 Standardization**：调整均值和方差，例如 Z-score。
- **归一化 Normalization**：把数值压到固定区间，或把整个样本缩放为单位范数。

它们通常只改变尺度，不应该改变样本的相对语义。

---

## 常见方法对比

| 方法 | 变换方式 | 主要优点 | 主要缺点 | 适用场景 |
|---|---|---|---|---|
| Z-score | 均值 0、标准差 1 | 通用，保留分布形状 | 对异常值敏感 | 线性模型、SVM、KNN、PCA、神经网络 |
| Min-Max | 映射到固定区间 | 有界、直观 | 极易受异常值影响 | 图像、神经网络、有明确上下界的特征 |
| RobustScaler | 使用中位数和四分位距 | 抗异常值 | 结果通常不在固定区间 | 金融、交易、传感器等长尾数据 |
| MaxAbs | 除以最大绝对值 | 不破坏稀疏性 | 对异常值敏感 | 稀疏矩阵、词频特征 |
| L1/L2 单位化 | 每个样本除以自身范数 | 强调方向而非绝对大小 | 丢失样本总量信息 | 文本向量、Embedding、余弦相似度 |
| Log 变换 | \(\log(1+x)\) | 压缩长尾和数量级差异 | 不能直接处理任意负数 | 收入、销量、点击量、金额 |
| Box-Cox | 学习幂变换参数 | 改善正偏态和异方差 | 要求数据严格大于 0 | 正值连续数据 |
| Yeo-Johnson | 类似 Box-Cox | 可处理零和负数 | 解释性下降 | 含零或负值的偏态数据 |
| Quantile Transform | 按排名映射到均匀或正态分布 | 强力处理异常值和非正态 | 扭曲原始距离，可能过拟合 | 明显非高斯且模型对分布敏感 |
| Whitening | 去相关并统一方差 | 消除线性相关性 | 噪声可能被放大，解释性差 | 特定信号处理、ICA、部分视觉任务 |

## 1. Z-score 标准化：默认首选

公式：

\[
x'=\frac{x-\mu}{\sigma}
\]

变换后，训练集上的特征通常具有：

- 均值约为 0；
- 标准差约为 1。

例如：

```text
年龄：     18～80
年收入：   3 万～300 万
```

如果不缩放，基于距离或梯度的模型可能主要被收入支配。Z-score 后，两者大致处于可比较的尺度。

### 优点

- 不压缩到固定区间，保留原分布形状；
- 大多数特征经变换后尺度相近；
- 适合大量机器学习算法；
- 对线性模型的正则化尤其重要。

### 缺点

均值和标准差容易受异常值影响。例如绝大多数工资在 5,000～30,000，但有一个值是 10,000,000，均值和标准差就会被明显拉动。

### 适用算法

- 线性回归、逻辑回归；
- Ridge、Lasso、Elastic Net；
- SVM；
- KNN、K-Means；
- PCA；
- 神经网络；
- 高斯过程等。

如果没有明显异常值，也没有特殊的范围要求，通常直接从它开始。

---

## 2. Min-Max 归一化：需要固定范围时使用

公式：

\[
x'=\frac{x-x_{\min}}
{x_{\max}-x_{\min}}
\]

通常映射到 \([0,1]\)，也可以映射到 \([-1,1]\)。

### 优点

- 输出范围确定；
- 保留原始数据的相对间隔；
- 输入范围与激活函数匹配时比较方便。

### 缺点

对极端值非常敏感：

```text
正常值：0～100
异常值：10000
```

映射到 \([0,1]\) 后，正常样本可能全部挤在 \(0～0.01\) 之间。

而且部署时遇到超出训练集范围的新数据，变换结果可能小于 0 或大于 1；Min-Max 并不天然保证未来数据永远位于目标区间。

### 适用场景

- 像素值从 0～255 转为 0～1；
- 已知物理上下限的传感器数据；
- 对输入范围敏感的神经网络；
- 确实需要输出落在指定区间的系统。

如果上下界只是当前样本的最小值和最大值，而不是稳定的业务边界，应谨慎使用。

---

## 3. RobustScaler：存在异常值时优先考虑

典型形式：

\[
x'=\frac{x-\operatorname{median}(x)}
{Q_3-Q_1}
\]

其中 \(Q_3-Q_1\) 是四分位距 IQR。

### 优点

中位数和四分位距不容易被少量极端值影响，因此适合：

- 金融交易金额；
- 用户消费；
- 房价；
- 传感器偶发尖峰；
- 长尾业务指标。

### 缺点

- 变换结果没有固定范围；
- 如果异常值本身就是重要业务信号，单纯缩放并不会解决建模问题；
- 对极端重尾数据，可能仍需先做截尾或对数变换。

RobustScaler 不是“删除异常值”，而只是避免异常值主导缩放参数。

---

## 4. MaxAbsScaler：稀疏数据常用

公式：

\[
x'=\frac{x}{\max|x|}
\]

变换后通常落在 \([-1,1]\)。

它不需要减去均值，因此原本的零仍然是零，不会把稀疏矩阵变成稠密矩阵。

适合：

- Bag-of-Words；
- TF、TF-IDF；
- 大规模 one-hot 特征；
- 其他稀疏矩阵。

对于稀疏数据，也可以使用：

```python
StandardScaler(with_mean=False)
```

不能直接对大型稀疏矩阵减均值，否则绝大多数零会变成非零值，造成巨大的内存开销。

MaxAbs 的缺点与 Min-Max 类似：最大绝对值容易受异常值影响。

---

## 5. L1/L2 单位化：按样本缩放

前面的方法通常是**按特征列**处理：

```text
对整列“年龄”计算均值和方差
```

单位化通常是**按样本行**处理：

\[
x'=\frac{x}{\lVert x\rVert_2}
\]

使每个样本的向量长度等于 1。

例如文本词频：

```text
文档 A：[100, 50, 0]
文档 B：[  2,  1, 0]
```

它们长度不同，但词汇比例一致。L2 单位化后，两者方向基本相同。

### 适用场景

- 文本向量；
- TF-IDF；
- 图像或文本 Embedding；
- 使用余弦相似度；
- 关心组成比例，而不是总量。

### 不适用场景

如果向量长度本身有意义，单位化会丢失信息。例如：

- 用户总消费额；
- 文档长度；
- 传感器整体强度；
- 交易总次数。

此时可以把“总量”额外保留为独立特征。

## 6. 对数变换：处理右偏长尾

对于金额、销量、浏览量等数据，常见分布是：

```text
大量小值 + 少量特别大的值
```

可使用：

\[
x'=\log(1+x)
\]

使用 `log1p` 是因为它能处理 0，并且在很小的 \(x\) 上数值更稳定。

### 作用

- 压缩数量级差异；
- 降低极端大值的影响；
- 减轻右偏；
- 有时能把乘法关系转为加法关系；
- 缓解回归中的异方差。

例如：

```text
原值：  1, 10, 100, 1000
log：约 0.69, 2.40, 4.62, 6.91
```

对数变换改变的是分布形状，不只是尺度。因此常见流程是：

```text
原始数据 → log1p → StandardScaler
```

如果存在负数：

- 数据有明确下界时，可以合理平移后取对数；
- 没有可靠下界时，优先考虑 Yeo-Johnson；
- 不要为了取对数随意加一个缺乏业务意义的常数。

---

## 7. Box-Cox 与 Yeo-Johnson

它们会自动寻找一个幂参数 \(\lambda\)，让数据更接近对称或正态。

### Box-Cox

要求：

\[
x>0
\]

适合严格为正的连续变量。

### Yeo-Johnson

可以处理：

- 正数；
- 0；
- 负数。

### 优点

- 比固定的对数变换更灵活；
- 常能改善偏态和异方差；
- 对线性模型、距离模型更有帮助。

### 缺点

- 变换后的特征不容易直接解释；
- 不保证真正变成正态分布；
- 参数必须只在训练集上估计；
- 决策树模型通常没有必要使用。

通常是：

```text
Power Transform → StandardScaler
```

部分工具的 PowerTransformer 已经默认包含标准化。

---

## 8. Quantile Transform：强力但要谨慎

它先根据样本排名估计经验分布，再映射到：

- 均匀分布；
- 或标准正态分布。

优点：

- 对异常值非常稳健；
- 可以强制改变边缘分布；
- 对明显非高斯的数据可能有效。

缺点：

- 会扭曲原始数值间距；
- 训练集之外的极端值容易被压到边界；
- 样本少时经验分布估计不稳定；
- 可能把噪声也塑造成看似规则的分布；
- 对结果的业务解释比较困难。

它更适合“排名比绝对差值重要”的场景，不适合作为无脑默认方案。

---

## 9. 哪些模型必须重视缩放

### 高度敏感

以下模型直接依赖距离、内积、梯度或正则化：

- KNN；
- K-Means；
- SVM；
- PCA；
- 线性/逻辑回归，尤其带正则化时；
- 神经网络；
- DBSCAN；
- 层次聚类；
- 高斯过程。

例如 KNN 使用欧氏距离。如果某一特征的量级大 1,000 倍，它可能完全控制邻居选择。

### 通常不敏感

基于树的模型主要按照阈值分裂：

- 决策树；
- 随机森林；
- XGBoost；
- LightGBM；
- CatBoost。

把“收入”从元换成万元，排序不变，树的分裂通常也不会发生实质改变。

但仍有例外：

- 使用了距离相关的预处理；
- 同时组合线性模型；
- 数值范围极端导致计算精度问题；
- 对特征做了有意义的 log 变换；
- 神经网络与树模型共用同一输入流程。

所以“树模型不需要标准化”通常成立，但“树模型不需要任何数据变换”并不成立。

## 10. 我会怎样选择

### 普通连续特征

```text
无明显异常值 → StandardScaler
```

这是最常见的默认选择。

### 有明显异常值

```text
异常值合理且应保留 → RobustScaler
异常值是数据错误   → 清理或修正后再缩放
异常值代表长尾     → log1p / PowerTransform → StandardScaler
```

不要用缩放代替异常值分析。

### 有稳定的物理上下限

```text
Min-Max
```

例如比例、像素、设备量程。但如果上下限来自当前训练样本，应考虑未来数据越界问题。

### 稀疏高维数据

```text
MaxAbsScaler
或 StandardScaler(with_mean=False)
```

文本 TF-IDF 往往已经带有 L2 单位化，不一定还需要额外标准化。

### 向量检索或余弦相似度

```text
L2 normalize
```

归一化后，向量内积等价于余弦相似度。

### 强偏态正值

```text
log1p → StandardScaler
```

如果简单对数不够灵活，再考虑 Box-Cox。

### 含零或负数的偏态数据

```text
Yeo-Johnson → StandardScaler
```

### 树模型

```text
通常保持原尺度
必要时处理偏态、异常值和业务特征
```

## 11. 最重要的工程规则：防止数据泄漏

缩放参数只能用训练集计算：

```text
训练集：fit + transform
验证集：只 transform
测试集：只 transform
线上数据：只 transform
```

错误做法是先对全量数据计算均值、标准差、最小值或分位数，再划分训练集和测试集。这会让测试集的信息提前进入训练流程。

正确做法是把预处理放进 Pipeline：

```python
Pipeline([
    ("scaler", StandardScaler()),
    ("model", LogisticRegression())
])
```

交叉验证时，每一折都必须单独拟合 scaler。

时间序列中还要更严格：某个时间点的数据只能使用过去数据估计缩放参数，不能使用未来数据。

## 12. 几个容易踩的坑

- **不要对 one-hot 的 0/1 列机械做 Z-score**：这会降低解释性，通常也没必要。
- **不要忘记单位差异**：米、毫米、万元等量纲差异会影响距离和正则化。
- **不要把每一行都做 L2 单位化当成默认操作**：它会删除样本总量信息。
- **不要为了“正态化”而变换所有特征**：多数模型并不要求每个输入严格正态。
- **不要把 BatchNorm、LayerNorm 与数据标准化混为一谈**：前者处理网络内部激活，不能完全替代正确的输入预处理。
- **不要对目标值使用输入特征的 scaler**：回归目标如果需要缩放，应使用独立的变换器，并在输出后执行逆变换。

最终可以用这条决策链：

```text
先问模型是否对尺度敏感
        ↓ 是
是否存在严重异常值？
  ├─ 否 → StandardScaler
  └─ 是 → 异常值是否属于合理长尾？
           ├─ 是 → log/幂变换，再 StandardScaler
           └─ 不方便变换 → RobustScaler

特殊情况：
固定范围 → Min-Max
稀疏数据 → MaxAbs
比较方向 → L2 normalize
```

核心不是追求某种形式上的“统一范围”，而是让缩放方式与**模型使用特征的方式、数据分布以及业务含义**相匹配。
