卷积、空洞卷积、深度可分离卷积、反卷积分别怎么做？在实际任务里你怎么取舍？


下面只用普通 Markdown 和 ASCII，避免 Mermaid 渲染问题。

先用一句话区分：

- 普通卷积：同时做空间特征提取和通道融合。
- 空洞卷积：在卷积核采样点之间留空，用较少参数扩大感受野。
- 深度可分离卷积：先逐通道做空间卷积，再用 `1×1` 卷积混合通道。
- 反卷积：更准确叫转置卷积，用可学习方式放大特征图。

## 1. 普通卷积

假设输入形状是：

```text
H × W × Cin
```

使用：

```text
K × K 卷积核
Cout 个输出通道
```

每个输出通道都会查看所有输入通道：

```text
输入通道 1 ─┐
输入通道 2 ─┼─→ 一个 K×K×Cin 卷积核 → 输出通道 1
...         │
输入通道 Cin┘
```

如果有 `Cout` 个卷积核，就得到 `Cout` 个输出通道。

不考虑 bias 时，参数量是：

```text
K × K × Cin × Cout
```

例如：

```text
K = 3
Cin = 64
Cout = 128
```

参数量：

```text
3 × 3 × 64 × 128 = 73,728
```

### 输出尺寸

单个空间维度：

```text
Hout = floor((H + 2P - D×(K-1) - 1) / S + 1)
```

其中：

- `K`：卷积核大小；
- `S`：stride；
- `P`：padding；
- `D`：dilation。

常见配置：

```text
kernel_size = 3
stride = 1
padding = 1
dilation = 1
```

可以保持高宽不变。

### 普通卷积做了什么

它同时完成：

1. 空间特征提取：观察周围像素；
2. 通道融合：组合所有输入通道的信息。

例如深层特征中，不同通道可能分别表示边缘、纹理和形状，普通卷积可以把这些信息一起组合。

### 优点

- 表达能力强；
- 空间和通道信息一次完成融合；
- GPU、NPU 上的实现非常成熟；
- 在中小型特征图上效率和精度通常都不错。

### 缺点

- 通道数较大时参数量和计算量高；
- 高分辨率特征图上的计算成本明显；
- 移动端模型中可能太重。

## 2. 空洞卷积

空洞卷积也叫 Dilated Convolution 或 Atrous Convolution。

普通 `3×3` 卷积的采样位置：

```text
x x x
x x x
x x x
```

dilation 为 2 时：

```text
x . x . x
. . . . .
x . x . x
. . . . .
x . x . x
```

其中 `.` 表示跳过的位置。

卷积核仍然只有 9 个权重，但覆盖范围从 `3×3` 变成了 `5×5`。

### 有效卷积核大小

```text
K_effective = D × (K - 1) + 1
```

例如 `K=3`：

| Dilation | 实际参数数 | 有效覆盖范围 |
|---:|---:|---:|
| 1 | 9 | 3×3 |
| 2 | 9 | 5×5 |
| 3 | 9 | 7×7 |
| 4 | 9 | 9×9 |

空洞卷积扩大感受野，但不会因为 dilation 增大而增加参数量。

### 与大卷积核的区别

一个普通 `7×7` 卷积有 49 个空间权重；一个 dilation=3 的 `3×3` 卷积只有9个空间权重，但有效范围也是 `7×7`。

代价是空洞卷积只采样其中9个位置，不会连续观察整个 `7×7` 区域。

### 优点

- 不降低分辨率就能扩大感受野；
- 不显著增加参数量；
- 适合需要像素级输出的任务；
- 可以组合多个 dilation 获取多尺度信息。

### 缺点

#### 栅格效应

连续使用相同 dilation 时，采样位置可能像棋盘一样相互错开，遗漏部分局部信息：

```text
只看部分格点
→ 相邻像素之间缺少交互
→ 输出可能出现不连续结构
```

缓解方法：

- 交替使用不同 dilation；
- 混合普通卷积；
- 使用多尺度并行分支；
- 采用 Hybrid Dilated Convolution；
- 使用 ASPP。

#### 显存和速度问题

空洞卷积没有降低特征图尺寸，因此后续层一直处理高分辨率特征，激活显存可能很高。

虽然理论 FLOPs 与同尺寸普通 `3×3` 卷积接近，但某些硬件或推理引擎对高 dilation 的优化不如普通卷积。

### 适用场景

- 语义分割；
- 医学图像分割；
- 目标检测；
- 音频和时间序列；
- 需要较大上下文但不能降低分辨率的任务。

DeepLab 中的 ASPP 就是典型应用：

```text
同一特征图
├─ dilation = 1
├─ dilation = 6
├─ dilation = 12
└─ dilation = 18
       ↓
    特征融合
```

## 3. 深度可分离卷积

深度可分离卷积把普通卷积分解成两步：

```text
输入
→ Depthwise Convolution
→ Pointwise 1×1 Convolution
→ 输出
```

## 第一步：Depthwise Convolution

每个输入通道单独使用自己的卷积核：

```text
输入通道 1 → 卷积核 1 → 中间通道 1
输入通道 2 → 卷积核 2 → 中间通道 2
...
输入通道 C → 卷积核 C → 中间通道 C
```

不同通道之间暂时不交换信息。

在常见框架中等价于：

```python
Conv2d(
    in_channels=Cin,
    out_channels=Cin,
    kernel_size=3,
    groups=Cin
)
```

参数量：

```text
K × K × Cin
```

## 第二步：Pointwise Convolution

使用 `1×1` 卷积融合通道：

```text
1 × 1 × Cin × Cout
```

参数量：

```text
Cin × Cout
```

总参数量：

```text
K×K×Cin + Cin×Cout
```

### 与普通卷积比较

对于：

```text
K = 3
Cin = 64
Cout = 128
```

普通卷积：

```text
3×3×64×128 = 73,728
```

深度可分离卷积：

```text
Depthwise：3×3×64   =   576
Pointwise：1×1×64×128 = 8,192
总计：8,768
```

参数量约缩小：

```text
73,728 / 8,768 ≈ 8.4 倍
```

计算量也会明显下降。

大致比例是：

```text
深度可分离卷积 / 普通卷积
≈ 1/Cout + 1/K²
```

当 `Cout` 较大、`K=3` 时，通常能节省大量计算。

### 优点

- 参数少；
- FLOPs 低；
- 适合移动端和边缘设备；
- 可以在相同预算下使用更多层或更宽通道；
- 高分辨率输入下节省明显。

### 缺点

#### 空间与通道建模被拆开

普通卷积可以在一次操作中联合学习：

```text
某个空间模式 + 某些通道组合
```

深度可分离卷积先独立处理空间，再融合通道，表达约束更强，可能导致精度下降。

#### FLOPs 少不一定实际延迟低

Depthwise 卷积的算术强度较低，容易受内存带宽限制。某些 GPU 对普通卷积优化非常好，Depthwise 卷积反而无法充分利用计算单元。

因此：

```text
参数量更少
≠ FLOPs 更少
≠ 真实设备一定更快
```

必须在目标手机、NPU、GPU 或推理引擎上测真实延迟。

#### 1×1 卷积可能成为主要成本

Depthwise 本身很便宜，但随后的 Pointwise 卷积需要混合通道。在 MobileNet 一类模型中，大量计算实际上消耗在 `1×1` 卷积上。

### 适用场景

- 手机和嵌入式设备；
- 实时视觉；
- 高分辨率轻量网络；
- MobileNet、Xception、EfficientNet；
- 对模型大小、功耗和延迟敏感的任务。

## 4. 反卷积，也就是转置卷积

“反卷积”这个名称容易误导。它通常并不是求普通卷积的数学逆，而是：

> 使用卷积对应线性变换的转置，将较小特征图映射到较大特征图。

更准确的名称是 Transposed Convolution。

### 普通卷积下采样

例如 stride=2：

```text
8×8
→ Conv stride=2
→ 4×4
```

转置卷积可以：

```text
4×4
→ Transposed Conv stride=2
→ 8×8
```

### 直观理解

可以近似理解为：

1. 在输入元素之间插入零；
2. 对扩大的特征图进行普通卷积；
3. 根据 padding 和 output padding 调整输出尺寸。

例如一维情况：

```text
原输入：
a b c

stride=2 插零：
a 0 b 0 c

再进行卷积：
得到更长的输出
```

实际实现通常不会真的构造完整插零矩阵，而是直接高效计算。

### 输出尺寸

单个空间维度：

```text
Hout =
(Hin - 1)×S
- 2P
+ D×(K - 1)
+ output_padding
+ 1
```

`output_padding` 主要用于解决 stride 大于 1 时多个输入尺寸可能映射到同一输出尺寸的歧义。它不是在输出边缘真正追加一圈零。

### 参数量

与对应普通卷积处于相同量级：

```text
K × K × Cin × Cout
```

具体权重维度排列依框架而异。

### 优点

- 上采样过程可以学习；
- 能同时扩大分辨率和提取特征；
- 适合生成模型和 Encoder–Decoder；
- 可以学习比固定插值更复杂的恢复方式。

### 缺点：棋盘格伪影

如果 kernel size 不能被 stride 整除，不同输出位置可能收到不同数量的卷积贡献：

```text
部分位置覆盖次数多
部分位置覆盖次数少
→ 产生棋盘格纹理
```

这在图像生成、分割边缘和重建任务中比较常见。

缓解方法：

- 让 kernel size 与 stride 合理匹配；
- 使用 `bilinear/nearest resize + 普通卷积`；
- 使用 PixelShuffle；
- 在输出端加入平滑卷积；
- 检查 padding 和 output padding。

### 替代方案

#### 插值后卷积

```text
低分辨率特征
→ Bilinear / Nearest 上采样
→ 3×3 普通卷积
```

优点：

- 输出尺寸更直观；
- 通常较少出现棋盘格；
- 在语义分割中很常用。

缺点：

- 插值本身不可学习；
- 上采样后的大特征图再卷积，计算量可能较高。

#### PixelShuffle

先在低分辨率空间产生更多通道，再重新排列到空间维度：

```text
H × W × (C×r²)
→ PixelShuffle
→ rH × rW × C
```

常用于超分辨率和图像生成。

## 5. 四者的核心差异

| 方式 | 主要目的 | 空间尺寸 | 通道混合 | 参数与计算 | 主要风险 |
|---|---|---|---|---|---|
| 普通卷积 | 通用特征提取 | 可保持或降低 | 是 | 较高 | 高分辨率时成本大 |
| 空洞卷积 | 扩大感受野 | 通常保持 | 是 | 与同核普通卷积接近 | 栅格效应、激活显存高 |
| 深度可分离卷积 | 降低计算量 | 可保持或降低 | 分两步完成 | 明显较低 | 精度下降、硬件未必更快 |
| 转置卷积 | 可学习上采样 | 增大 | 是 | 中等或较高 | 棋盘格伪影 |

## 6. 实际项目怎么取舍

## 图像分类

默认方案：

```text
普通 3×3 卷积
+ 分阶段 stride=2 下采样
+ Global Average Pooling
```

原因：

- 分类不要求恢复像素级位置；
- 普通卷积表达能力强；
- 逐步降低分辨率可以控制计算量。

如果是服务器端、精度优先：

```text
优先普通卷积或成熟 Backbone
```

如果是移动端、实时场景：

```text
优先深度可分离卷积
```

空洞卷积和转置卷积在纯分类中通常不是重点。

## 语义分割

分割既需要大范围语义，又需要精确空间位置。

常见组合：

```text
Encoder：
普通卷积 + 有限下采样

瓶颈：
空洞卷积 / ASPP

Decoder：
双线性上采样 + 普通卷积
或转置卷积

跳跃连接：
恢复浅层细节
```

我的取舍通常是：

- 需要扩大感受野但不能继续下采样：空洞卷积；
- 更重视稳定、少伪影：插值加普通卷积；
- 希望上采样可学习且已验证无伪影：转置卷积；
- 移动端分割：深度可分离卷积加轻量 Decoder。

## 目标检测

检测需要多尺度特征。

通常：

- Backbone 使用普通卷积或深度可分离卷积；
- 使用 stride 卷积形成多尺度特征；
- 小目标多时减少早期下采样；
- 需要更大感受野时，在高层加入空洞卷积；
- FPN 上采样通常使用 nearest/bilinear 加卷积。

检测中通常不会大量依赖转置卷积，因为 FPN 的插值上采样更简单稳定。

## 医学图像

医学分割对边缘和细节敏感。

常见选择：

- U-Net 主体使用普通卷积；
- 瓶颈使用空洞卷积获取更大上下文；
- Decoder 使用插值加卷积，或经过验证的转置卷积；
- 保留 Skip Connection；
- 避免过度下采样导致小病灶消失。

如果是 3D CT/MRI，3D 普通卷积和3D转置卷积显存非常昂贵，可以考虑：

- 2.5D 输入；
- 分块训练；
- 各向异性卷积；
- 深度可分离或分解卷积；
- 混合精度和梯度检查点。

## 超分辨率和图像生成

可选：

- 转置卷积；
- PixelShuffle；
- 插值加卷积。

通常：

- 超分辨率优先考虑 PixelShuffle；
- 生成模型可以使用转置卷积，但必须检查棋盘格；
- 追求稳定输出时，插值加卷积通常更安全。

## 移动端和边缘设备

优先：

```text
Depthwise 3×3
→ Pointwise 1×1
```

但最终选择必须依据目标硬件测试：

- 端到端延迟；
- 峰值内存；
- 功耗；
- 算子是否被 NPU 支持；
- 量化后精度；
- 模型加载时间。

如果目标硬件对 Depthwise 支持不好，普通卷积或 Group Convolution 可能反而更快。

## 时间序列和音频

- 局部模式：普通 1D 卷积；
- 需要较长历史但不想堆很多层：空洞 1D 卷积；
- 端侧语音：深度可分离 1D/2D 卷积；
- 序列上采样或生成：转置卷积，但注意周期性伪影。

WaveNet 一类模型就是空洞因果卷积的典型应用。

## 7. 一个实用决策顺序

```text
首先问：要不要改变分辨率？

不改变：
├─ 精度和通用性优先 → 普通卷积
├─ 需要更大感受野   → 空洞卷积
└─ 算力和模型大小受限 → 深度可分离卷积

降低分辨率：
├─ 通用模型 → stride 普通卷积
└─ 轻量模型 → stride depthwise + pointwise

提高分辨率：
├─ 稳定、少伪影 → 插值 + 普通卷积
├─ 希望学习上采样 → 转置卷积
└─ 超分辨率 → PixelShuffle
```

我的默认策略通常是：

1. 先用普通卷积建立精度基线；
2. 感受野不足但不能下采样时加入空洞卷积；
3. 需要移动端部署时，将高计算层替换为深度可分离卷积；
4. 上采样默认先尝试插值加卷积；
5. 转置卷积只有在验证确实提高任务指标、且没有明显伪影时才保留；
6. 最终同时比较精度、真实设备延迟、峰值内存和输出伪影，而不是只比较参数量或 FLOPs。
