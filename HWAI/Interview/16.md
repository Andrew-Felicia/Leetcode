什么是特征工程？常见的特征工程方法有哪些？


特征工程（Feature Engineering）是：

> **把原始数据转换成更适合模型学习的特征表示，并筛除无效、冗余或泄漏信息的过程。**

它连接了原始数据和模型：

```text
原始数据
→ 清洗
→ 特征转换
→ 特征构造
→ 特征选择
→ 模型训练
```

例如预测用户是否流失，原始数据可能是：

```text
用户 ID
注册时间
每次登录时间
订单记录
客服记录
```

直接输入模型未必有效。经过特征工程后可以得到：

```text
注册天数
最近一次登录距今天数
近7天登录次数
近30天消费金额
消费金额环比变化
最近是否投诉
```

后者更直接地表达了与流失相关的业务信号。

## 一、特征工程主要包括什么

通常可以分为四类：

| 类型 | 作用 |
|---|---|
| 特征清洗 | 处理缺失、异常、重复和错误数据 |
| 特征转换 | 改变特征尺度或分布 |
| 特征构造 | 从已有字段生成更有意义的新特征 |
| 特征选择/降维 | 删除无用、冗余或高噪声特征 |

## 二、缺失值处理

常见方法：

### 数值特征

- 均值填充；
- 中位数填充；
- 分组统计量填充；
- KNN 或模型填充；
- 使用固定业务值；
- 保留缺失指示变量。

例如：

```text
收入 = 中位数填充
收入是否缺失 = 1
```

缺失本身可能具有预测意义。例如没有填写收入的用户，可能与填写收入的用户存在系统性差异。

### 类别特征

通常增加独立类别：

```text
UNKNOWN
MISSING
NOT_APPLICABLE
```

需要区分：

- 未采集；
- 不适用；
- 采集失败；
- 用户拒绝提供。

把这些情况全部填成同一个值，可能丢失业务信息。

---

## 三、异常值处理

先判断异常值属于：

- 数据采集错误；
- 单位错误；
- 合理但极端的长尾数据；
- 真正需要识别的异常事件。

常见处理：

- 删除明确错误的数据；
- 使用业务上下限截断；
- 分位数截尾；
- `log1p` 变换；
- RobustScaler；
- 增加异常标记。

例如消费金额呈长尾：

```text
10、20、30、100、100000
```

可以使用：

```text
log_amount = log(1 + amount)
```

需要注意：欺诈检测、设备故障检测中，异常值本身可能是最重要的信号，不能机械删除。

---

## 四、数值特征缩放

### Z-score 标准化

```text
x_new = (x - mean) / std
```

适合：

- 线性回归、逻辑回归；
- SVM；
- KNN；
- K-Means；
- PCA；
- 神经网络。

### Min-Max 归一化

```text
x_new = (x - min) / (max - min)
```

通常映射到 `[0,1]`，适合具有稳定上下界的数据。

### RobustScaler

使用中位数和四分位距，适合存在异常值的特征。

### 树模型

决策树、Random Forest、XGBoost、LightGBM 通常不依赖特征尺度，因此一般不需要专门标准化。

---

## 五、分布变换

某些模型更容易学习对称、平滑或接近线性的关系。

常见方法：

- `log1p`；
- 平方根；
- Box-Cox；
- Yeo-Johnson；
- 分位数变换；
- Rank Transform。

例如：

```text
原始收入：1千、1万、10万、100万
```

模型可能更关心数量级，可以构造：

```text
log_income = log(1 + income)
```

分布变换与标准化不同：

- 标准化主要改变尺度；
- 对数和幂变换会改变分布形状及样本间距离。

---

## 六、离散化和分箱

把连续变量转换成区间：

```text
年龄：
0～18    → 未成年
19～30   → 青年
31～50   → 中年
51以上   → 其他
```

常见分箱方法：

- 等宽分箱；
- 等频分箱；
- 基于业务规则；
- 基于决策树；
- WOE 分箱。

优点：

- 降低异常值影响；
- 能表达非线性关系；
- 提高可解释性；
- 适合评分卡等场景。

缺点：

- 丢失连续信息；
- 边界附近可能不连续；
- 分箱过细容易过拟合；
- 分箱规则需要只在训练集上确定。

通常可以同时保留：

```text
原始连续特征
+
分箱后的类别特征
```

让模型自行选择。

## 七、类别特征编码

### One-hot Encoding

```text
城市 = 北京、上海、深圳

→ 城市_北京
→ 城市_上海
→ 城市_深圳
```

适合低基数类别。

缺点是高基数特征会导致维度膨胀。

### Ordinal Encoding

```text
低 = 0
中 = 1
高 = 2
```

只适合确实具有顺序的类别。

不能随意把：

```text
北京 = 0
上海 = 1
深圳 = 2
```

输入线性或距离模型，因为这会制造不存在的大小和距离关系。

### 频次编码

```text
category_frequency
= 该类别出现次数或比例
```

适合高基数特征，但会把频次相同的不同类别映射成相同值。

### 目标编码

例如对城市构造：

```text
该城市用户的平均购买率
```

表达能力强，但非常容易泄漏标签。必须使用：

- Out-of-Fold 编码；
- 时间安全编码；
- 平滑；
- 最小样本约束。

### 哈希编码

把类别哈希到固定数量的桶中。

优点是维度固定、能处理新类别；缺点是存在哈希冲突。

### Embedding

神经网络中可以给每个类别学习一个低维向量，适合：

- 用户 ID；
- 商品 ID；
- 高基数类别；
- 推荐系统。

---

## 八、交叉特征与组合特征

单个特征可能信息不足，特征之间的关系更重要。

常见构造：

### 加减乘除

```text
客单价 = 总消费金额 / 订单数
负债率 = 总负债 / 总资产
点击率 = 点击数 / 展示数
价格折扣 = 原价 - 售价
```

除法时需要处理分母为零：

```text
ratio = numerator / (denominator + epsilon)
```

或者对零分母单独增加标记。

### 乘积特征

```text
面积 × 单价
```

可以表达两个变量共同作用。

### 差值

```text
实际值 - 计划值
当前消费 - 上月消费
申请时间 - 注册时间
```

### 类别交叉

```text
地区 × 商品类别
设备类型 × 操作系统
渠道 × 用户等级
```

One-hot 后的线性模型本身不能自动表达复杂交互，因此交叉特征可能很重要。

树模型可以自动学习一部分交互，但显式构造的业务比率和统计特征仍可能有效。

### 多项式特征

例如：

```text
x
x²
x³
x1×x2
```

适合低维数据和线性模型。维度较高时组合数量会快速爆炸，容易过拟合。

---

## 九、聚合统计特征

这类特征在表格数据、推荐系统和风控中非常重要。

例如按用户聚合订单：

```text
历史订单数
总消费金额
平均订单金额
最大订单金额
消费金额标准差
近7天订单数
近30天活跃天数
不同商品类别数
退款比例
```

常用统计量：

- count；
- sum；
- mean；
- median；
- min/max；
- standard deviation；
- quantile；
- unique count；
- 最近一次发生时间；
- 时间间隔；
- 趋势和变化率。

需要特别防止时间泄漏。

预测时间为 `T` 时，只能使用 `T` 之前的数据：

```text
错误：
用整个月订单统计预测月中是否购买

正确：
只用预测时点之前的历史订单
```

## 十、时间特征

从时间戳可以构造：

```text
年、月、日
星期几
小时
是否周末
是否节假日
月初/月末
季度
距上次事件时间
注册至今天数
```

### 周期编码

小时是周期变量：

```text
23 点与 0 点距离很近
```

直接编码为 `23` 和 `0` 会让模型认为它们距离很远。可以使用：

```text
hour_sin = sin(2π × hour / 24)
hour_cos = cos(2π × hour / 24)
```

同样适用于：

- 星期；
- 月份；
- 季节；
- 经纬方向等周期变量。

### 滞后和窗口特征

时间序列中常用：

```text
昨天的值
7天前的值
过去7天均值
过去30天最大值
环比变化
同比变化
滚动标准差
```

所有窗口都必须只使用过去数据。

## 十一、文本特征

传统机器学习常用：

- Bag-of-Words；
- TF-IDF；
- Word N-gram；
- Character N-gram；
- 文档长度；
- 词汇数量；
- 标点比例；
- 关键词计数；
- 情感词特征；
- 主题模型；
- Word2Vec、FastText；
- 预训练模型 Embedding。

例如垃圾邮件分类可以构造：

```text
是否包含链接
链接数量
大写字母比例
感叹号数量
TF-IDF
文本 Embedding
```

使用预训练语言模型时，不应过度清洗文本，因为大小写、标点、空格和否定词都可能包含语义。

## 十二、图像和音频特征

### 图像

传统方法包括：

- 颜色直方图；
- HOG；
- SIFT；
- 边缘；
- 纹理；
- 形状；
- 关键点。

现代方法通常使用 CNN 或 ViT 提取 Embedding，再用于分类、检索或聚类。

也可以加入元数据：

```text
图像宽高
宽高比
亮度
对比度
文件大小
拍摄时间
设备类型
```

但要检查元数据是否存在数据泄漏。

### 音频

常见特征：

- MFCC；
- Mel Spectrogram；
- 音高；
- 能量；
- 过零率；
- 频谱质心；
- 时长；
- 预训练音频 Embedding。

## 十三、特征选择

特征越多不一定越好。无效特征会：

- 增加过拟合；
- 增加训练和推理成本；
- 降低可解释性；
- 引入数据漂移和维护成本。

### Filter 方法

不依赖具体模型：

- 方差过滤；
- 相关系数；
- 卡方检验；
- ANOVA；
- 互信息；
- 缺失率；
- 唯一值比例。

优点是快，缺点是通常只分析单个特征与目标的关系，可能忽略特征交互。

### Wrapper 方法

通过反复训练模型选择特征：

- 前向选择；
- 后向消除；
- RFE；
- 基于交叉验证的特征子集搜索。

优点是更贴近模型效果，缺点是计算成本高且可能过拟合验证集。

### Embedded 方法

利用模型训练过程选择特征：

- L1/Lasso；
- 决策树特征重要性；
- Random Forest；
- GBDT；
- XGBoost；
- 稳定性选择。

需要注意，树模型基于分裂次数或增益的特征重要性可能偏向高基数和连续特征。可以配合：

- Permutation Importance；
- SHAP；
- 特征消融。

---

## 十四、降维与特征提取

### PCA

把相关特征映射到少量正交方向，保留尽可能多的方差。

适合：

- 高维连续特征；
- 特征高度相关；
- 可视化；
- 降低噪声和计算量。

缺点是主成分不容易解释，而且最大方差方向未必是最有预测价值的方向。

### Truncated SVD

常用于 TF-IDF 等稀疏矩阵，不需要先对稀疏数据减均值。

### Autoencoder

神经网络通过重建输入学习低维表示，能表达非线性降维。

### 预训练 Embedding

使用语言、图像或音频基础模型，把原始数据转为语义向量。

降维与特征选择的区别是：

- 特征选择：保留部分原始特征；
- 降维：生成新的组合特征。

## 十五、不同模型对特征工程的依赖

### 线性模型

非常依赖：

- 缩放；
- 缺失值；
- 类别编码；
- 非线性变换；
- 交叉特征；
- 共线性处理。

### KNN、K-Means、SVM

对尺度和距离非常敏感，标准化通常必不可少。

### 树模型

通常不需要缩放，能够自动学习：

- 阈值；
- 非线性；
- 部分特征交互。

但仍然非常依赖：

- 高质量聚合特征；
- 时间窗口特征；
- 合理类别编码；
- 数据清洗；
- 防止泄漏。

### 深度学习

可以自动学习表示，但仍需要：

- 正确的数据表示；
- 合理归一化；
- 数据增强；
- 序列截断和 mask；
- 类别 Embedding；
- 多模态对齐；
- 标签和数据质量控制。

“深度学习不需要特征工程”并不准确。很多人工构造转移到了网络结构、数据管道、预训练和表示学习中。

## 十六、实际项目中的流程

我通常会按以下顺序：

1. 明确预测时间点、目标和可使用的数据范围。
2. 按用户、时间或业务实体正确划分训练和验证集。
3. 检查缺失、异常、重复、标签错误和数据泄漏。
4. 建立只使用基础特征的基线模型。
5. 根据业务构造聚合、比率、时间窗口和交叉特征。
6. 根据模型选择缩放与类别编码。
7. 使用交叉验证和时间外测试做特征消融。
8. 删除无效、泄漏、成本过高或线上不可获得的特征。
9. 把全部变换放进可复现的 Pipeline。
10. 上线后监控特征分布、缺失率和漂移。

评价一个特征时，不应只问“验证指标有没有提升”，还要问：

- 线上能否稳定获得？
- 是否存在未来信息？
- 计算成本多高？
- 是否容易漂移？
- 对不同时间、人群和地区是否稳定？
- 删除它后性能下降多少？
- 它的业务含义是否合理？

核心原则是：

> **好的特征不是越复杂越好，而是能以稳定、可复现且无泄漏的方式，把与目标有关的信息表达得更直接。**
