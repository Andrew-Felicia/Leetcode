为什么训练更倾向用 GPU 而不是 CPU？从算力模型与内存带宽解释下。



核心原因不是“GPU 主频更高”，而是：

> **深度学习训练主要由大规模矩阵乘法组成，追求吞吐量而不是单条指令延迟。GPU 拥有大量并行计算单元、更高的显存带宽，以及专门的矩阵计算单元，因此更匹配训练负载。**

可以从两个维度理解：

1. 算力模型：GPU 如何同时完成大量相似计算；
2. 内存模型：GPU 如何快速给这些计算单元供应数据。

## 一、训练主要在算什么

以一个线性层为例：

\[
Y=XW
\]

假设：

\[
X\in\mathbb R^{B\times K},
\qquad
W\in\mathbb R^{K\times N}
\]

计算量约为：

\[
2BKN\ \text{FLOPs}
\]

因为每个输出元素都需要 \(K\) 次乘法和加法。

Transformer 中的大部分计算都可以转成矩阵乘法：

- Q、K、V 投影；
- Attention 中的 \(QK^T\)；
- Attention 权重乘 V；
- MLP 的上投影和下投影；
- 输出 LM Head。

CNN 中的卷积也通常会被转换或实现为高度优化的矩阵乘加。

这些计算具有共同特点：

- 运算量大；
- 各输出元素相对独立；
- 控制分支少；
- 数据结构规则；
- 同一条指令会作用在大量数据上。

这正是 GPU 擅长的负载。

---

# 二、CPU 和 GPU 的设计目标不同

## CPU：优化低延迟和复杂控制

CPU 通常拥有相对较少但非常强大的核心，每个核心包含：

- 复杂的分支预测；
- 乱序执行；
- 较大的多级缓存；
- 高单线程性能；
- 较强的通用控制能力。

CPU 擅长：

- 操作系统和业务逻辑；
- 复杂分支；
- 数据结构遍历；
- 不规则内存访问；
- 少量任务的低延迟处理；
- 串行依赖强的程序。

可以把 CPU 理解为：

```text
少量能力很强的员工
每个人都能处理复杂、不同的任务
```

## GPU：优化吞吐量和数据并行

GPU 拥有大量相对简单的计算单元，按 SM、Warp 等层次组织。

大量线程以 SIMT 方式执行：

```text
同一条指令
作用于大量不同的数据元素
```

GPU 擅长：

- 矩阵乘法；
- 卷积；
- 向量运算；
- 大批量、规则、重复的数值计算。

可以把 GPU 理解为：

```text
大量专门化员工
同时执行相似、规则的任务
```

单个 GPU 线程未必比单个 CPU 核心快。GPU 的优势来自于同时运行大量线程，用总体吞吐量取胜。

---

# 三、GPU 如何并行计算矩阵乘法

矩阵乘法：

\[
C_{ij}=\sum_kA_{ik}B_{kj}
\]

不同的 \(C_{ij}\) 可以并行计算：

```text
线程 1 → C[0,0]
线程 2 → C[0,1]
线程 3 → C[0,2]
...
线程 n → C[i,j]
```

实际 GPU 实现不会简单地“一个线程算一个元素”，而会进行分块：

```text
A 的一个 Tile
×
B 的一个 Tile
→
C 的一个 Tile
```

每个数据块加载到高速片上存储后，会被多个计算单元重复使用。

这样可以减少对显存的重复访问。

## Tensor Core

现代训练 GPU 通常还有专门的矩阵计算单元，例如 Tensor Core。

它们可以高效执行类似：

\[
D=A\times B+C
\]

的矩阵乘加操作，并针对以下低精度格式提供很高的吞吐量：

- FP16；
- BF16；
- TF32；
- FP8；
- 某些整数格式。

因此 GPU 不只是“核心更多”，还包含专门为矩阵运算设计的硬件。

---

# 四、峰值算力为什么重要

算力通常用 FLOPS 表示：

\[
\text{FLOPS}
=
\text{每秒浮点运算次数}
\]

训练一次模型需要：

- 前向传播；
- 反向传播；
- 梯度计算；
- 参数更新。

反向传播通常与前向传播处于相同量级，甚至更贵。因此一次训练 step 可能需要非常多的浮点运算。

CPU 的单核很强，但核心数量有限；GPU 可以同时启动大量线程，并使用矩阵单元完成大量乘加，所以矩阵计算的总吞吐量通常高得多。

不过，峰值 FLOPS 并不等于实际训练速度。计算单元必须持续获得数据，否则再高的理论算力也会闲置。

这就涉及内存带宽。

---

# 五、内存带宽是什么

内存带宽表示单位时间内能从内存读取或写入多少数据：

\[
\text{Bandwidth}
=
\frac{\text{传输字节数}}{\text{时间}}
\]

训练过程中需要读写：

- 模型参数；
- 输入数据；
- 中间激活；
- 梯度；
- 优化器状态；
- Attention 矩阵；
- KV 或临时工作区。

CPU 通常使用 DDR 内存，特点是：

- 容量大；
- 单位容量成本低；
- CPU 访问延迟相对低；
- 总带宽通常低于训练 GPU 的显存带宽。

训练 GPU 通常使用 GDDR 或 HBM，特点是：

- 带宽很高；
- 非常适合大量并行、连续的数据访问；
- 容量相对有限；
- 单位容量成本高。

因此 GPU 可以更快地将大批量参数和激活送入计算单元。

---

# 六、为什么只看带宽还不够

需要同时考虑“每读取一个字节，可以做多少计算”，这称为算术强度：

\[
\text{Arithmetic Intensity}
=
\frac{\text{FLOPs}}{\text{Bytes transferred}}
\]

例如：

- 矩阵乘法：一个数据块可以被重复使用，算术强度高；
- ReLU：读取一个数、做一个简单运算、再写回，算术强度低；
- 参数更新：读参数、梯度、优化器状态，再写回，通常受带宽限制。

硬件能够达到的性能大致受到 Roofline 模型约束：

\[
\text{实际性能}
\le
\min
\left(
\text{峰值算力},
\text{内存带宽}\times\text{算术强度}
\right)
\]

这产生两种情况。

## 计算受限 Compute-bound

算术强度高，主要瓶颈是计算单元：

```text
数据已经准备好
但矩阵乘法还没算完
```

典型操作：

- 大型矩阵乘法；
- 大通道卷积；
- 大批量线性层。

GPU 的 Tensor Core 在这里优势最明显。

## 带宽受限 Memory-bound

算术强度低，计算很简单，主要时间花在搬数据：

```text
算一下很快
但读写数据比较慢
```

典型操作：

- 激活函数；
- Dropout；
- 残差相加；
- LayerNorm 的部分阶段；
- Softmax；
- 优化器更新；
- Embedding 查找。

这类操作即使增加计算单元，速度也不一定提高，必须减少内存访问或进行算子融合。

---

# 七、GPU 的内存层次

GPU 并不是每次计算都直接访问显存，而是具有多层存储：

```text
寄存器
↓
Shared Memory / L1 Cache
↓
L2 Cache
↓
HBM / GDDR 显存
↓
CPU 主存
↓
磁盘
```

越靠上：

- 速度越快；
- 容量越小；
- 越需要精心管理。

高性能矩阵乘法的关键是：

1. 从显存把数据加载到片上；
2. 在寄存器和 Shared Memory 中反复使用；
3. 做尽可能多的乘加；
4. 最后才把结果写回显存。

如果每做一次乘法都要重新访问显存，GPU 的计算单元会大量等待。

这也是 CUDA、cuBLAS、cuDNN、FlashAttention 等优化的核心之一：**减少慢速内存访问，提高片上数据复用。**

---

# 八、GPU 如何隐藏内存延迟

GPU 的单次显存访问延迟并不一定很低。它主要通过大量并发线程隐藏延迟。

当一组线程等待内存时，GPU 可以切换去执行另一组已经准备好的线程：

```text
Warp A：等待内存
Warp B：执行计算
Warp C：执行计算
Warp D：等待内存
```

因此 GPU 需要足够大的工作量，才能同时保持很多 Warp 处于活跃状态。

这解释了为什么：

- 大 batch 通常更容易发挥 GPU；
- 太小的模型可能用不满 GPU；
- batch size 为 1 时，GPU 利用率可能较低；
- 大型规则矩阵通常比许多零散小矩阵效率高。

GPU 更擅长吞吐量，而不是每个微小操作的最低延迟。

---

# 九、Batch Size 为什么影响 GPU 利用率

Batch Size 增大后：

- 矩阵规模增大；
- 并行线程更多；
- kernel 启动成本被摊薄；
- 权重可以被更多样本复用；
- 更容易用满计算单元。

例如线性层：

\[
[B,K]\times[K,N]
\]

当 \(B\) 很小时，可能没有足够工作填满 GPU；当 \(B\) 增大后，矩阵乘法效率通常提高。

但 Batch Size 不能无限增大，因为：

- 激活占用显存；
- 可能改变优化和泛化行为；
- 过大的 batch 可能需要调整学习率；
- 数据并行通信量可能上升。

显存不够时常使用梯度累积，但它只能模拟较大的优化 batch，不一定能完全获得一次大矩阵计算的硬件效率。

---

# 十、混合精度为什么能显著加速

假设同样存储一组数据：

- FP32：每个元素 4 字节；
- FP16/BF16：每个元素 2 字节；
- FP8：每个元素 1 字节。

降低精度有两方面收益。

## 减少内存流量

FP16 相比 FP32，参数和激活的传输字节数约减半：

\[
\text{相同带宽下可传输更多元素}
\]

## 提高矩阵计算吞吐量

Tensor Core 通常对 FP16、BF16、FP8 等格式提供更高吞吐。

因此混合精度同时改善：

- 计算瓶颈；
- 内存带宽瓶颈；
- 显存容量瓶颈。

训练中常使用：

- 低精度保存和计算激活；
- 更高精度累加；
- 必要时保留高精度主权重；
- FP16 使用 Loss Scaling 防止梯度下溢；
- BF16 因指数范围较大，通常更容易稳定训练。

---

# 十一、算子融合为什么重要

假设需要执行：

```text
线性层输出
→ Bias
→ 激活函数
→ Dropout
→ 残差相加
```

如果每一步都是单独的 GPU kernel：

1. 从显存读数据；
2. 做一个简单操作；
3. 写回显存；
4. 下一步再读回来。

大量时间消耗在显存读写和 kernel 启动上。

融合后：

```text
一次读入
→ 连续完成多个操作
→ 一次写回
```

这对带宽受限操作非常有效。

常见优化包括：

- Fused Adam；
- Fused LayerNorm；
- Bias + Activation 融合；
- FlashAttention；
- 卷积、归一化和激活融合；
- 编译器自动算子融合。

FlashAttention 的重要价值之一，就是避免把完整 Attention 矩阵频繁写入和读出 HBM，更多地在片上分块完成计算。

---

# 十二、CPU 与 GPU 之间的数据传输也是瓶颈

CPU 和独立 GPU 通常拥有各自的内存：

```text
磁盘
→ CPU 内存
→ PCIe
→ GPU 显存
→ 计算
```

PCIe 带宽通常远低于 GPU 显存内部带宽。因此，如果每个小操作都在 CPU 和 GPU 之间来回拷贝，GPU 的优势会被抵消。

训练时通常应该：

- 模型常驻 GPU；
- 尽量让整个计算图在 GPU 上执行；
- 使用较大的数据批次；
- 使用 pinned memory；
- 异步预取下一批数据；
- 让数据加载与 GPU 计算重叠；
- 避免训练循环中频繁调用 CPU 标量或同步操作。

例如频繁执行“把 GPU Tensor 转到 CPU 打印数值”，可能强制等待前面的 GPU 任务完成，破坏异步流水线。

---

# 十三、训练为什么比推理更需要 GPU

训练需要保存更多中间状态，并执行反向传播。

以 Adam 为例，除参数外通常还需要：

- 梯度；
- 一阶动量；
- 二阶动量；
- 可能还有高精度主权重；
- 前向传播保存的激活。

因此训练的：

- 计算量更大；
- 内存占用更高；
- 内存读写更多；
- 并行机会更多。

推理只需要前向传播。如果模型很小、请求批量很小，而且特别关注单请求延迟，CPU 可能已经足够。

---

# 十四、什么时候 CPU 可能更合适

GPU 并非所有任务都更快。以下情况 CPU 可能更合适：

## 模型和数据很小

GPU kernel 启动和数据传输的开销可能超过实际计算。

例如：

- 小型线性回归；
- 小决策树；
- 少量样本的简单模型；
- 极小的神经网络。

## 控制流复杂

例如：

- 大量条件分支；
- 递归；
- 图遍历；
- 不规则数据结构；
- 每个样本执行不同逻辑。

这类任务难以转化为规则的大规模并行运算。

## 稀疏、随机访存非常严重

Embedding 查找、超大稀疏模型或推荐系统可能受制于内存容量和随机访问，而不是矩阵峰值算力。

## 内存容量比带宽更重要

CPU 主存通常比单张 GPU 显存大得多。模型或数据无法放入 GPU 时，CPU 或 CPU+GPU 混合方案可能更现实。

## 小批量、低延迟推理

Batch size 为 1、模型较小且 CPU 已有优化时，CPU 可能具有更好的成本和部署便利性。

---

# 十五、多 GPU 后瓶颈会转向通信

单张 GPU 放不下或训练太慢时，可以使用多 GPU。

数据并行中，每张 GPU：

1. 处理不同数据；
2. 计算本地梯度；
3. 通过 All-Reduce 同步梯度。

此时训练速度受到：

- GPU 间互联带宽；
- 通信延迟；
- 梯度大小；
- 计算与通信是否重叠；
- 节点内和节点间网络差异。

可以近似理解为：

\[
T_{\text{step}}
\approx
T_{\text{compute}}
+
T_{\text{communication}}
-
T_{\text{overlap}}
\]

当 GPU 计算越来越快时，梯度同步和参数通信可能成为新的瓶颈。

因此大型训练还会使用：

- NVLink 等高速互联；
- 梯度通信与反向计算重叠；
- ZeRO；
- Tensor Parallel；
- Pipeline Parallel；
- Sequence Parallel；
- 梯度压缩或低精度通信。

---

# 十六、一个完整的性能判断框架

看到一个训练操作时，可以依次问：

### 1. 并行性够不够？

是否有大量相互独立、结构相同的计算？

- 是：适合 GPU；
- 否：CPU 可能更合适。

### 2. 算术强度高不高？

\[
\frac{\text{计算量}}{\text{数据传输量}}
\]

- 高：更可能受算力限制；
- 低：更可能受内存带宽限制。

### 3. 矩阵规模够不够大？

小矩阵和小 batch 可能无法充分利用 GPU。

### 4. 数据是否频繁跨 CPU/GPU？

频繁传输和同步会抵消 GPU 优势。

### 5. 能否使用低精度和算子融合？

这通常可以同时改善算力、带宽和显存占用。

### 6. 数据加载是否跟得上？

如果 GPU 经常等待磁盘、解码或 CPU 数据增强，瓶颈并不在 GPU。

最终可以这样记：

> **CPU 用复杂核心换取低延迟和通用性；GPU 用大量并行单元换取吞吐量。深度学习训练的大矩阵运算具有高并行性，而高带宽显存、片上数据复用和专用矩阵单元又能持续向这些计算单元供数，所以 GPU 通常远比 CPU 适合训练。**

但 GPU 的理论算力只有在矩阵足够大、数据布局合理、传输足够少、显存带宽得到利用时，才能真正转化成训练速度。
