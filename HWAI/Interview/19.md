给我讲讲多头注意力的计算流程与复杂度瓶颈；常见的降复杂度做法（比如低秩、稀疏、线性注意力）各有什么代价？



多头注意力（Multi-Head Attention，MHA）的核心是：

> 把隐藏维度拆成多个子空间，让不同 Attention Head 并行学习不同关系，最后再把各头结果拼接起来。

它的主要瓶颈不一定总是 `N²`：短序列下，QKV 投影和 MLP 可能更贵；长序列下，Attention 矩阵的计算与显存才成为主导。

## 1. 输入和符号

设输入：

```text
X shape = [B, N, D]
```

其中：

- `B`：batch size；
- `N`：序列长度；
- `D`：模型隐藏维度；
- `H`：Attention head 数；
- `Dh = D / H`：每个 head 的维度。

例如：

```text
B  = 8
N  = 2048
D  = 4096
H  = 32
Dh = 128
```

## 2. 第一步：生成 Q、K、V

通过三个线性投影：

```text
Q = X @ Wq
K = X @ Wk
V = X @ Wv
```

形状：

```text
X:  [B, N, D]
Wq: [D, D]
Q:  [B, N, D]
```

K、V 相同。

计算复杂度：

```text
Q、K、V 三次投影：
O(3 × B × N × D²)
```

参数量：

```text
3 × D²
```

工程中通常将三个投影融合成一次矩阵乘法：

```text
QKV = X @ Wqkv
```

其中：

```text
Wqkv shape = [D, 3D]
```

这样数学计算量基本不变，但可以减少 kernel 启动和内存访问。

---

## 3. 第二步：拆分多个 Head

将：

```text
[B, N, D]
```

变成：

```text
[B, H, N, Dh]
```

例如：

```text
[B, 2048, 4096]
→
[B, 32, 2048, 128]
```

每个 Head 有各自的 Q、K、V 子空间：

```text
head_i = Attention(Q_i, K_i, V_i)
```

多个 Head 可以学习不同关系，例如：

- 局部词法；
- 长距离依赖；
- 指代关系；
- 语法结构；
- 代码括号匹配；
- 特定位置模式。

但不能机械认为每个 Head 一定具有清晰、固定且可解释的功能。

---

## 4. 第三步：计算 Attention Score

每个 Head 计算：

```text
S = Q @ K^T / sqrt(Dh)
```

形状：

```text
Q:   [B, H, N, Dh]
K^T: [B, H, Dh, N]

S:   [B, H, N, N]
```

其中：

```text
S[b, h, i, j]
```

表示第 `b` 个样本、第 `h` 个 Head 中，第 `i` 个 Query 对第 `j` 个 Key 的相关性。

计算复杂度：

```text
O(B × H × N² × Dh)
```

因为：

```text
H × Dh = D
```

所以可以写成：

```text
O(B × N² × D)
```

Attention Score 的元素数量是：

```text
B × H × N²
```

这正是长序列显存压力的来源。

---

## 5. 第四步：Mask 和 Softmax

Decoder-only 模型加入因果 Mask：

```text
第 i 个 Query 只能访问位置 j <= i
```

然后：

```text
A = softmax(S + mask)
```

形状仍是：

```text
[B, H, N, N]
```

Softmax 复杂度约为：

```text
O(B × H × N²)
```

因果 Mask 虽然屏蔽了上三角，但如果使用普通稠密实现，复杂度仍然是 `O(N²)`，只是理论有效元素和常数有所减少。

---

## 6. 第五步：加权汇总 V

计算：

```text
O = A @ V
```

形状：

```text
A: [B, H, N, N]
V: [B, H, N, Dh]

O: [B, H, N, Dh]
```

复杂度同样为：

```text
O(B × H × N² × Dh)
= O(B × N² × D)
```

因此 Attention 主体有两次主要矩阵乘法：

```text
Q @ K^T
A @ V
```

总复杂度仍记为：

```text
O(B × N² × D)
```

---

## 7. 第六步：合并 Head 并输出投影

将：

```text
[B, H, N, Dh]
```

转换回：

```text
[B, N, D]
```

然后：

```text
Y = concat(heads) @ Wo
```

输出投影复杂度：

```text
O(B × N × D²)
```

完整 MHA 的主要计算可以写成：

```text
线性投影：
O(B × N × D²)

Attention：
O(B × N² × D)
```

更细一点：

```text
QKV 投影： 约 3BND²
输出投影：约 BND²
QK^T：     约 BN²D
AV：       约 BN²D
```

总计约：

```text
4BND² + 2BN²D
```

这里省略常数和硬件实现差异。

---

# 8. 什么时候哪个部分是瓶颈

比较：

```text
投影成本：O(ND²)
注意力成本：O(N²D)
```

二者比例由 `N` 和 `D` 决定。

## 当 N 远小于 D

例如：

```text
N = 512
D = 4096
```

通常 QKV 投影、输出投影和 MLP 占更大计算量。

此时只优化 `N²` Attention，端到端收益可能有限。

## 当 N 接近或大于 D

例如：

```text
N = 32768
D = 4096
```

Attention 的二次复杂度开始占主导，Attention Score 的显存也会非常大。

## MLP 也很贵

Transformer Block 除 Attention 外通常还有 MLP：

```text
D → 4D → D
```

其复杂度约为：

```text
O(B × N × D²)
```

因此短、中序列下，MLP 可能比 Attention 更耗算力。

---

# 9. 训练与推理的瓶颈不同

## 训练和 Prefill

整段序列并行计算：

```text
Q、K、V 都是长度 N
```

主要问题是：

- `N²` Attention 计算；
- `N²` 中间激活；
- 反向传播保存；
- GPU 显存；
- 多卡通信。

## 自回归 Decode

使用 KV Cache 后，每步只有一个新 Query：

```text
q_t shape = [B, H, 1, Dh]
```

它查询历史长度 `N` 的 KV：

```text
score shape = [B, H, 1, N]
```

单步 Attention 复杂度变为：

```text
O(B × N × D)
```

不再是单步 `O(N²D)`，但每生成一个 token 都需要读取越来越长的 KV Cache。

Decode 的瓶颈通常是：

- 模型权重读取；
- KV Cache 读取；
- 显存带宽；
- 请求调度；
- 小矩阵计算效率。

因此推理时很多优化主要减少 KV Cache，而不一定减少训练阶段的 `N²` Attention。

---

# 10. FlashAttention：精确但不降渐近复杂度

FlashAttention 不改变 Attention 的数学结果，也不把 `O(N²)` 变成线性。

它的核心是分块计算：

```text
Q、K、V 分块加载到片上 SRAM
→ 分块计算 Attention
→ 在线维护 Softmax 统计量
→ 不把完整 N×N 矩阵写回 HBM
```

复杂度仍是：

```text
O(N²D)
```

但中间 Attention 矩阵不需要完整落到显存，显存通常从：

```text
O(N²)
```

降低到更接近：

```text
O(ND)
```

主要收益：

- 减少 HBM 读写；
- 降低训练显存；
- 提高实际速度；
- 保持精确 Softmax Attention；
- 不需要改变模型行为。

代价：

- 仍有二次计算量；
- 极长序列依然昂贵；
- 对硬件、数据类型、head size 和 kernel 支持有要求；
- 某些自定义 Attention 逻辑不容易融合。

实际项目中，如果标准 Attention 能表达任务需求，我通常先使用 FlashAttention，而不是立刻改成近似 Attention。

---

# 11. 局部或滑动窗口 Attention

每个 token 只关注附近 `W` 个 token：

```text
token i
只看
[i-W, ..., i, ..., i+W]
```

复杂度从：

```text
O(N²D)
```

变成：

```text
O(NWD)
```

当 `W` 是固定值时，对 `N` 近似线性。

## 优点

- 实现和语义直观；
- 适合文本、语音、图像等局部相关性强的数据；
- 缓存和计算可明显下降；
- 相比线性 Attention，仍保留标准 Softmax。

## 代价

### 长距离信息不能直接交互

两个距离很远的 token 必须经过多层才能交换信息。

如果每层窗口宽度为 `W`，有效感受野会随层数扩大，但不如全局 Attention 直接。

### 可能遗漏关键远程依赖

例如：

- 长文档开头与结尾；
- 代码中的跨文件或跨函数引用；
- 长对话早期指令；
- 远距离实体对应。

### 窗口边界问题

固定窗口可能让边界附近的信息交换受限。常见缓解方法有：

- Shifted Window；
- Dilated Window；
- Overlapping Window；
- 周期性插入全局层。

适合：

- 长文本的局部建模；
- 流式语音；
- 高分辨率图像；
- 局部结构占主导的任务。

---

# 12. 稀疏 Attention

稀疏 Attention 只计算部分 Query–Key 对。

典型模式：

```text
局部窗口
+ 少量全局 token
+ 随机连接
+ 特定任务连接
```

如果每个 Query 只访问 `K` 个 Key：

```text
复杂度约 O(NKD)
```

## 常见形式

### 固定稀疏

连接模式提前确定：

- Sliding Window；
- Block Sparse；
- Dilated Attention；
- 局部加全局；
- 图结构 Attention。

优点：

- 可以提前规划内存；
- 比动态稀疏更容易实现；
- 在合适 kernel 下效率较好。

缺点：

- 稀疏模式依赖人工设计；
- 可能屏蔽任务需要的依赖；
- 不同任务最优模式不同。

### 动态稀疏或 Top-k Attention

根据内容选择最相关的 Key：

```text
每个 Query 只保留 Top-k Key
```

理论上可以降低计算，但有一个关键问题：

> 如果为了找 Top-k，先计算完整的 `QK^T`，计算量仍然是 `O(N²)`。

要真正降复杂度，需要使用：

- 近似最近邻；
- 分层路由；
- 聚类；
- Hashing；
- 可学习 Router。

代价包括：

- 路由本身有成本；
- 稀疏索引不规则；
- GPU 利用率可能较差；
- 训练可能不稳定；
- Top-k 选择通常不可微或梯度不连续。

---

# 13. Block Sparse Attention

将序列分成 Block，只计算部分 Block 之间的 Attention：

```text
Query Block 1 → Key Block 1、2
Query Block 2 → Key Block 1、2、3
Query Block 3 → Key Block 2、3、全局块
```

相比逐 token 稀疏，Block Sparse 更适合 GPU，因为块内仍然可以使用稠密矩阵乘法。

优点：

- 更容易利用 Tensor Core；
- 比 token 级稀疏访问更规则；
- 可以结合局部、全局和因果模式。

代价：

- 块内仍可能计算很多无用位置；
- Block 大小需要调节；
- 模式设计影响准确率；
- 不同硬件对稀疏 kernel 的支持差异较大；
- 理论 FLOPs 下降不一定转化为等比例速度提升。

---

# 14. 低秩 Attention

低秩方法假设 Attention 矩阵或序列维度存在冗余。

标准 Attention：

```text
QK^T shape = [N, N]
```

如果能用秩为 `R` 的结构近似，其中 `R << N`，可以把计算降到接近：

```text
O(NRD)
```

## Linformer 类型

将 K、V 沿序列维度从 `N` 投影到 `R`：

```text
K: [N, D] → [R, D]
V: [N, D] → [R, D]
```

然后：

```text
QK^T shape = [N, R]
```

而不是 `[N,N]`。

### 优点

- 计算和显存从二次变为近似线性；
- 矩阵仍比较规则，容易使用稠密计算；
- 对某些冗余序列有效。

### 代价

- 假设 Attention 近似低秩，不一定总成立；
- 投影可能丢失少量但关键的 token；
- 固定序列投影对可变长度和长度外推较麻烦；
- Causal Attention 实现更复杂；
- 精确检索、复制和尖锐 Attention 可能退化。

## Nyström 类型

选取少量 Landmark Token，用它们近似完整 Attention 矩阵。

复杂度通常接近：

```text
O(NMD)
```

其中 `M` 是 Landmark 数。

代价：

- Landmark 选择影响很大；
- 需要近似矩阵逆或伪逆；
- 数值稳定性更复杂；
- 局部细节和罕见依赖可能丢失。

## 参数低秩不等于 Attention 低复杂度

将：

```text
Wq ≈ A @ B
```

做低秩分解，只能降低 QKV 投影参数和 `ND²` 部分计算。

如果仍然计算完整：

```text
QK^T
```

Attention 仍是：

```text
O(N²D)
```

LoRA 也是参数更新的低秩化，并不会自动降低标准 Attention 的序列复杂度。

---

# 15. 线性 Attention

标准 Attention 是：

```text
softmax(QK^T) V
```

Softmax 使矩阵运算不能简单改变乘法顺序。

线性 Attention 使用特征映射 `phi` 近似：

```text
softmax(q · k)
≈ phi(q)^T phi(k)
```

于是可以将：

```text
(phi(Q) @ phi(K)^T) @ V
```

重新结合为：

```text
phi(Q) @ (phi(K)^T @ V)
```

先计算：

```text
S = phi(K)^T @ V
```

再计算：

```text
output = phi(Q) @ S
```

这样就不需要显式构建 `[N,N]` Attention 矩阵。

## 复杂度

设特征映射维度为 `R`：

```text
时间复杂度约 O(N × R × D)
显存复杂度约 O(NR + RD)
```

当 `R` 和 `D` 固定时，对序列长度 `N` 近似线性。

## 因果线性 Attention

可以维护前缀累积状态：

```text
S_t = S_(t-1) + phi(k_t)^T v_t
Z_t = Z_(t-1) + phi(k_t)
```

每个 token 只更新固定大小状态。

这使线性 Attention 同时具有：

- 训练时并行扫描；
- 推理时递归更新；
- 不保存完整 KV Cache 的潜力。

## 代价

### 不再是精确 Softmax Attention

特征映射只是近似，可能改变模型表达能力。

### 容易丢失尖锐检索能力

标准 Softmax 可以让某个 Query 几乎只关注一个特定 token。线性近似可能让注意力更平滑，在以下任务中容易吃亏：

- 精确复制；
- 键值检索；
- 长上下文 Needle-in-a-Haystack；
- 代码符号定位；
- 精确实体对应。

### 数值稳定性

分母归一化、前缀累积和低精度训练都可能引入稳定性问题。

### 实际复杂度可能是 `O(ND²)`

如果特征映射维度 `R` 与 `D` 同量级：

```text
O(NRD) ≈ O(ND²)
```

它对 `N` 是线性的，但隐藏维度较大时仍然不便宜。

### 硬件效率未必理想

标准稠密 Attention 有高度优化的 FlashAttention 内核。理论上 FLOPs 更少的线性 Attention，如果 kernel、数据布局和融合不好，实际速度未必更快。

---

# 16. Performer 和随机特征

Performer 使用随机特征近似 Softmax Kernel：

```text
exp(q · k)
≈ phi(q)^T phi(k)
```

优点：

- 序列复杂度接近线性；
- 比简单核函数更接近 Softmax；
- 可以用于因果 Attention。

代价：

- 近似存在方差；
- 随机特征数量越多，质量越好但计算越贵；
- 小特征维度下精度可能下降；
- 数值稳定和实现复杂度高于标准 Attention；
- 对随机种子和正交特征实现可能敏感。

---

# 17. LSH / Hash Attention

例如 Reformer 类型方法，将相似的 Query、Key 哈希到同一个 Bucket：

```text
相似 token
→ 相同或相近 Bucket
→ 只在 Bucket 内计算 Attention
```

复杂度可以接近：

```text
O(N log N × D)
```

优点：

- 内容相关，而不是固定窗口；
- 可以发现距离很远但内容相似的 token。

代价：

- 哈希碰撞和漏召回；
- 排序、分桶有额外成本；
- 动态控制流对 GPU 不够友好；
- 训练和调试复杂；
- 因果 Mask、Padding 和可变长度处理更麻烦；
- 相似性用于分桶，但分桶本身就是近似。

---

# 18. Token 压缩和池化

不是修改 Attention 公式，而是减少 token 数量：

```text
N 个 token
→ 池化、合并或选择
→ M 个 token，M << N
→ 对 M 个 token 做标准 Attention
```

复杂度从：

```text
O(N²D)
```

变为：

```text
压缩成本 + O(M²D)
```

常见方式：

- Patch Merging；
- Token Pooling；
- Token Pruning；
- 聚类；
- Top-k Token；
- Perceiver Latent；
- Cross-Attention 压缩到少量 Latent。

适合图像、视频和含大量冗余的序列。

代价：

- 被删除的细节很难恢复；
- Token 选择错误可能造成永久信息丢失；
- 检测、分割和精确定位任务更敏感；
- 动态 Token 数使 batching 和 kernel 优化更复杂。

---

# 19. MQA、GQA 和 MLA

这些方法主要解决推理 KV Cache，而不是训练阶段的 `N²` Attention。

## MHA

```text
每个 Query Head 都有独立 K、V Head
```

KV Cache 大小与 `H` 成正比。

## MQA

```text
多个 Query Head 共享一组 K、V
```

KV Cache 显著减少。

代价：

- K/V 表达能力受限；
- 质量可能略有下降；
- 所有 Query Head 共享同一份检索表示。

## GQA

```text
多个 Query Head 分组共享 K、V
```

它在 MHA 和 MQA 之间折中：

- KV Cache 明显减少；
- 质量通常更接近 MHA；
- 现代大模型中很常见。

## MLA

将 K、V 压缩到潜在表示，再通过结构设计恢复或吸收进投影。

目标是进一步减少：

- KV Cache；
- Decode 时内存带宽；
- 多卡通信。

代价是：

- 架构和 kernel 更复杂；
- 不是现有 MHA 模型随意替换就能获得的优化；
- 需要从训练阶段采用或进行专门适配。

重要的是：

```text
GQA/MQA/MLA 减少 KV Cache 和投影成本
但每个 Query 仍要读取、比较历史位置
```

所以它们不一定把序列维度的 Attention 从二次变成线性。

---

# 20. KV Cache 压缩、量化和淘汰

推理时还可以：

- FP16 KV 改为 FP8/INT8；
- 只保留重要 token；
- 合并相似 token；
- 使用 Sliding Window；
- 将旧 KV 移到 CPU；
- 分层缓存；
- 使用低秩 KV。

优点：

- 增加并发；
- 支持更长上下文；
- 降低显存带宽。

代价：

- 量化误差；
- 长期信息丢失；
- KV 搬运延迟；
- 稀疏索引开销；
- 不同任务对淘汰策略敏感；
- 精确回忆能力可能下降。

# 21. 方法对比

| 方法 | 序列复杂度 | 是否精确 Softmax | 主要收益 | 主要代价 |
|---|---:|---:|---|---|
| 标准 Attention | `O(N²D)` | 是 | 表达能力强 | 计算、显存二次增长 |
| FlashAttention | `O(N²D)` | 是 | 降低 IO 和激活显存 | 不改变二次计算量 |
| 滑动窗口 | `O(NWD)` | 局部范围内是 | 简单、高效 | 长距离交互变慢 |
| 固定稀疏 | `O(NKD)` | 稀疏范围内是 | 控制计算模式 | 可能遗漏依赖 |
| 动态 Top-k | 取决于检索 | 部分 | 内容相关稀疏 | 找 Top-k 本身可能很贵 |
| Block Sparse | 取决于块数 | 稀疏范围内是 | 更适合 GPU | 块内浪费、kernel 要求 |
| 低秩 Attention | `O(NRD)` | 近似 | 压缩序列交互 | 低秩假设可能失效 |
| 线性 Attention | `O(NRD)` | 通常否 | 对 N 近似线性 | 精确检索和稳定性可能下降 |
| LSH Attention | 约 `O(N log N D)` | 近似 | 内容相关远程连接 | 哈希、排序和漏召回 |
| Token Pooling | 约 `O(M²D)` | 压缩后是 | 直接减少 token | 细节不可逆丢失 |
| MQA/GQA | 训练仍可能 `O(N²D)` | 是 | 减少 KV Cache | K/V 表达能力受限 |
| KV 量化/淘汰 | Decode 更省内存 | 可能近似 | 增加并发和上下文 | 质量与召回风险 |

# 22. 实际任务怎么选

## 普通上下文，精度优先

```text
标准 MHA/GQA
+ FlashAttention
```

这是默认首选，因为：

- 数学上精确；
- 模型能力稳定；
- 训练和推理生态成熟；
- 不引入近似误差。

## 高分辨率图像

优先考虑：

- Window Attention；
- Shifted Window；
- 层次化 Token；
- Patch Merging；
- 局部加少量全局 Attention。

因为图像具有很强局部性，而且 Token 数随分辨率快速增长。

## 长文本但依赖以局部为主

可以使用：

```text
Sliding Window
+ 少量 Global Token
+ 周期性 Full Attention Layer
```

比完全线性化更稳妥。

## 需要精确长距离检索

例如：

- 长代码；
- 法律合同；
- 跨文档实体；
- Needle-in-a-Haystack。

应谨慎使用强近似线性 Attention。优先尝试：

- FlashAttention；
- GQA；
- 分布式 Ring Attention；
- RAG；
- 局部加全局；
- 分层检索；
- Prefix Cache。

## 移动端和边缘设备

可以考虑：

- MQA/GQA；
- 小窗口 Attention；
- 低秩 QKV 投影；
- Token Pooling；
- 混合 CNN–Attention；
- KV 量化。

但必须在目标硬件测真实延迟。理论 FLOPs 小，不代表移动端 kernel 一定快。

## 自回归大模型推理

重点往往不是训练时的 `N²`，而是：

- KV Cache 容量；
- Decode 内存带宽；
- Batch 调度；
- Prefix Cache；
- GQA/MQA/MLA；
- KV 量化；
- PagedAttention。

## 极长序列

如果达到数十万或百万 token，单纯依赖全局标准 Attention 通常成本很高。可结合：

```text
局部 Attention
+ 检索
+ 压缩记忆
+ 少量全局 token
+ 线性/状态空间模块
```

通常混合结构比完全依赖单一近似方法更可靠。

---

最重要的判断是：

> **优化 Attention 前，先确认瓶颈到底是 QKV/MLP 的 `ND²`、Attention 的 `N²D`、训练激活显存，还是推理 KV Cache 与内存带宽。**

如果序列不长，换成线性 Attention 可能几乎没有收益，反而损害精度；如果只是显存 IO 问题，FlashAttention 就可能足够；如果是 Decode KV Cache 问题，应优先考虑 GQA、KV 量化和调度，而不是直接修改训练阶段的 Attention 公式。
