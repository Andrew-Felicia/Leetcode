# 21. 加速优化问题：解答与详解

## 一、题目本质

这是**分组背包**问题的变形：

- 每个中转段是一个"组"，**必须且只能选一种**方式。
- 延误风险相当于"重量"，总和不能超过 T。
- 运费相当于"价值"，要让总和**最小**。

难点在于风险是**浮点数**，不能直接当数组下标。

## 二、思路：只保留"有用"的状态（帕累托前沿）

我们一段一段地往后算，每一步维护一个状态列表，每个状态是 `(累计风险, 累计运费)`。

**核心剪枝：** 如果状态 X 的风险更高，运费也更高，那 X 永远不可能比另一个状态更好，直接丢掉。

举例：`(0.3, 400)` 和 `(0.3, 370)`，风险一样但前者更贵，丢掉前者。又如 `(0.4, 380)` 和 `(0.3, 370)`，前者风险高、运费也高，同样丢掉。

剩下的状态按风险从小到大排列，运费严格递减。每处理一个中转段：

1. 把当前所有状态和该段每种方式两两组合。
2. 风险超过 T 的直接丢弃。
3. 按风险排序，扫描一遍，只保留运费比之前所有状态都低的。
4. 全部处理完后，最后一个状态（风险最大、运费最低）的运费就是答案。

**为什么不用普通背包 DP：** 普通做法要把风险乘以 100 之类变成整数下标，一旦风险精度高（如 0.001234）或 T 很大，数组会爆内存和时间。帕累托法直接用浮点数，状态数最多只有"不同风险值的个数"，通常很小，所以比较快。

**浮点误差处理：** 0.15 + 0.3 + 0.05 在计算机里可能得到 0.5000000000000001，会被误判为超过阈值 0.5（示例 2 正好卡在这里）。所以比较时用 `risk <= T + 1e-9`。

## 三、参考代码（Python）

```python
import sys

def main():
    data = sys.stdin.read().split()
    pos = 0
    L = int(data[pos]); pos += 1
    T = float(data[pos]); pos += 1
    EPS = 1e-9

    states = [(0.0, 0.0)]  # (累计风险, 累计运费)

    for _ in range(L):
        K = int(data[pos]); pos += 1
        opts = []
        for _ in range(K):
            # data[pos] 是方式名称，不参与计算
            r = float(data[pos + 1])
            c = float(data[pos + 2])
            pos += 3
            opts.append((r, c))

        # 两两组合，丢掉超过阈值的
        cand = []
        for r0, c0 in states:
            for r, c in opts:
                nr = r0 + r
                if nr <= T + EPS:
                    cand.append((nr, c0 + c))

        if not cand:
            print("-1.00")   # 题目未说明无解输出，这里是假设
            return

        # 按风险升序（风险相同则运费升序），只保留运费不断刷新最低的
        cand.sort()
        new_states = []
        best = float('inf')
        for r, c in cand:
            if c < best:
                new_states.append((r, c))
                best = c
        states = new_states

    print("%.2f" % states[-1][1])

main()
```

## 四、用样例手算验证

**样例 1**（T=0.4）：

- 第 1 段处理后：`(0.1, 300)`、`(0.25, 120)`，互不支配，都保留。
- 第 2 段组合：`(0.15, 550)`、`(0.3, 400)`、`(0.3, 370)`、`(0.45, 420)`（风险超过 0.4，丢弃）。
- 排序扫描：`(0.15, 550)` 保留；`(0.3, 370)` 运费更低，保留；`(0.3, 400)` 不比 370 低，丢弃。
- 最后一个状态运费 **370.00**，与样例一致。

**样例 2**（T=0.5）：第 1 段只有一种，状态为 `(0.15, 80)`。后面两段组合后，满足阈值的最低运费为 350，输出 **350.00**，与样例一致。

## 五、复杂度与注意点

- 时间：每段约为 `状态数 × K × log`，状态数受剪枝控制，一般不大。
- 空间：只保存当前的状态列表。
- 输入里的方式名称（如 `express`）只是标签，读入后跳过即可。
- 题目没写"无解"时的输出，我假设输出 `-1.00`。如果题目有明确要求，请改成对应格式。
- 如果数据规模很大（L 和 K 都上千）导致 Python 超时，可以改写成 C++，思路完全不变。需要的话告诉我。
