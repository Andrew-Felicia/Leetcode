This problem looks similar to “Maximum Subarray Sum”, but multiplication is trickier because:

```text id="bd7gce"
negative × negative = positive
```

So a VERY SMALL negative product can suddenly become a HUGE positive product later.

That changes everything.

---

# First example

```python id="jlwmn3"
nums = [2,3,-2,4]
```

Best product:

```text id="jlwm8o"
2 × 3 = 6
```

---

# Why normal Kadane fails

For sums:

```text id="u9kjlwm"
negative sums are always bad
```

But for products:

```text id="jlwm2m"
negative products may become good later
```

Example:

```python id="xjlwm9"
[-2,3,-4]
```

Observe:

```text id="jlwmso"
(-2) × 3 = -6
```

Looks terrible.

But then:

```text id="l3jlwm"
-6 × (-4) = 24
```

Suddenly huge.

So we must keep BOTH:

1. maximum product ending here
2. minimum product ending here

because the minimum negative product might become the next maximum.

---

# Core idea

At every position:

We track:

```text id="jlwm3k"
max_product_ending_here
min_product_ending_here
```

---

# Transition formula

At every number:

We consider:

1. start fresh from current number
2. multiply by previous maximum
3. multiply by previous minimum

So:

maxProd=\max(num,\ num\cdot prevMax,\ num\cdot prevMin)

and:

minProd=\min(num,\ num\cdot prevMax,\ num\cdot prevMin)

---

# Clean solution

```python id="4vjlwm"
class Solution:
    def maxProduct(self, nums: List[int]) -> int:

        curMax = nums[0]
        curMin = nums[0]
        ans = nums[0]

        for i in range(1, len(nums)):

            num = nums[i]

            tmpMax = max(
                num,
                num * curMax,
                num * curMin
            )

            tmpMin = min(
                num,
                num * curMax,
                num * curMin
            )

            curMax = tmpMax
            curMin = tmpMin

            ans = max(ans, curMax)

        return ans
```

# Why zero works automatically

Example:

```python id="jlwm7u"
[-2,0,-1]
```

At zero:

```text id="f8jlwm"
anything * 0 = 0
```

So the chain resets naturally.

---

# Important intuition

For sum problems:

```text id="jlwm1y"
negative bad
```

For product problems:

```text id="jlwm5g"
negative might become future positive
```

That is why we track BOTH max and min.
