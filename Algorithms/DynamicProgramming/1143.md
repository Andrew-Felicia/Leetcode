This problem is called **Partition Labels**. The constraint *"each letter appears in at most one part"* gives us a huge hint.

If a part contains the letter `'a'`, then **every single `'a'` in the entire string must be trapped inside this same part**. Therefore, the moment we look at a letter, the current part *must* extend at least as far as the absolute **last occurrence** of that letter in the string.

This leads us to a beautiful **Greedy Strategy** that runs in $O(n)$ time.

---

### The Strategy

1. **Find the Last Occurrences:** First, scan through the string once and record the last index where each character appears.
2. **Expand the Boundary:** Scan through the string a second time. As you look at each character, update your "current boundary" (`end`) to be the maximum of your current boundary and the last occurrence of this new character.
3. **Cut the String:** The moment your moving index `i` catches up to your boundary `end`, it means you have successfully trapped all the characters you've seen so far. You make a cut right there, record the size, and reset your starting point for the next chunk.

---

### Visualizing Example 1: `s = "ababcbacadefegdehijhklij"`

Let's look at how the boundary expands during the second pass:

* We start walking. At `i = 0`, we see `'a'`. The last `'a'` in the string is at index **8**. So, our chunk *must* go at least up to index 8 (`end = 8`).
* At `i = 1`, we see `'b'`. The last `'b'` is at index 5. Our boundary is already 8, which is further, so we keep `end = 8`.
* We keep walking, and the boundary stays 8 because no character we meet forces us to stretch further.
* When we finally reach `i = 8`, **our index matches our boundary (`i == end`)**. We cut here! The size of this first chunk is $8 - (-1) = 9$.
* We reset our starting point and repeat the process for the remaining letters.

---

### Python 3 Implementation

```python
class Solution:
    def partitionLabels(self, s: str) -> list[int]:
        # Step 1: Record the last occurrence of each character
        last_seen = {char: index for index, char in enumerate(s)}
        
        partitions = []
        start = 0
        end = 0
        
        # Step 2: Scan the string to find the natural break points
        for i, char in enumerate(s):
            # The current partition must extend to the last occurrence of the current character
            end = max(end, last_seen[char])
            
            # If we reach the end of the stretched boundary, we make a cut
            if i == end:
                partitions.append(i - start + 1)
                start = i + 1  # The next partition starts at the next index
                
        return partitions

```

### C++ Implementation

Instead of a heavy hash map, we can use a small fixed-size array of 26 integers since the constraints mention only lowercase English letters.

```cpp
#include <vector>
#include <string>
#include <algorithm>

class Solution {
public:
    std::vector<int> partitionLabels(std::string s) {
        // Step 1: Record the last occurrence of each character
        int last_seen[26] = {0};
        for (int i = 0; i < s.length(); ++i) {
            last_seen[s[i] - 'a'] = i;
        }
        
        std::vector<int> partitions;
        int start = 0;
        int end = 0;
        
        // Step 2: Scan the string to find the break points
        for (int i = 0; i < s.length(); ++i) {
            end = std::max(end, last_seen[s[i] - 'a']);
            
            if (i == end) {
                partitions.push_back(i - start + 1);
                start = i + 1;
            }
        }
        
        return partitions;
    }
};

```

---

### Complexity Analysis

* **Time Complexity:** $O(n)$ — We pass through the string exactly twice (once to map the last positions, once to cut chunks).
* **Space Complexity:** $O(1)$ — The dictionary/array tracks at most 26 lowercase English letters, requiring a constant amount of memory regardless of how long the string is.


Let's break down exactly how this grid system works and why the code functions the way it does.

Dynamic Programming can feel abstract because it solves a problem by looking backward at previous answers. To make it clear, let’s look at why we use a 2D grid, how the math rules work, and track a single example step-by-step.

---

## 1. Why a 2D Grid?

When comparing two separate strings, your progress can be at different positions in each string. For example, you might have processed 3 letters of `text1` but only 1 letter of `text2`.

A 2D grid allows us to map **every possible combination of progress** between the two strings.

* Each **row** represents how much of `text1` we have looked at.
* Each **column** represents how much of `text2` we have looked at.
* The value inside a cell `dp[i][j]` answers this exact question: *"If I only look at the first `i` letters of text1 and the first `j` letters of text2, what is the longest common subsequence length?"*

We add an extra row and column at the very beginning (labeled **Ø** for "empty string") initialized to `0`. If one of the strings is completely empty, the length of a common subsequence is automatically `0`.

---

## 2. The Two Rules of the Grid

As the nested loops move cell-by-cell through the grid, the code evaluates only one thing: **Do the two letters corresponding to this cell match?**

### Rule 1: The Letters Match (`text1[i-1] == text2[j-1]`)

If the characters match, this letter is a keeper! It adds to our subsequence length.

* **The Math:** `dp[i][j] = 1 + dp[i-1][j-1]`
* **What this means physically:** We look diagonally up and to the left (`dp[i-1][j-1]`), which represents the best score we had *before* including these two matching letters, and we add `1` to it.

### Rule 2: The Letters Do NOT Match (`text1[i-1] != text2[j-1]`)

If they don't match, this specific combination yields no new points. We must look back at our best previous configurations to carry the best score forward.

* **The Math:** `dp[i][j] = max(dp[i-1][j], dp[i][j-1])`
* **What this means physically:** We look at the cell directly above us (`dp[i-1][j]`, which means dropping the current letter of `text1`) and the cell directly to our left (`dp[i][j-1]`, which means dropping the current letter of `text2`). We pick whichever score is larger.

---

## 3. Step-by-Step Trace: `text1 = "abcde"`, `text2 = "ace"`

Let's watch the grid fill up manually so you can see the ripple effect.

```
      Ø   a   c   e
  Ø [ 0,  0,  0,  0 ]
  a [ 0,  ?,  .,  . ]
  b [ 0,  .,  .,  . ]
  c [ 0,  .,  .,  . ]
  d [ 0,  .,  .,  . ]
  e [ 0,  .,  .,  . ]

```

### Row 1: Dealing with 'a' from `text1`

* **'a' vs 'a' (Match!):** Look diagonally up-left (0) and add 1 $\rightarrow$ **1**.
* **'a' vs 'c' (No Match):** Take max of top (0) and left (1) $\rightarrow$ **1**.
* **'a' vs 'e' (No Match):** Take max of top (0) and left (1) $\rightarrow$ **1**.
* *Row 1 becomes:* `[0, 1, 1, 1]`

### Row 2: Dealing with 'b' from `text1`

* **'b' vs 'a' (No Match):** Take max of top (1) and left (0) $\rightarrow$ **1**.
* **'b' vs 'c' (No Match):** Take max of top (1) and left (1) $\rightarrow$ **1**.
* **'b' vs 'e' (No Match):** Take max of top (1) and left (1) $\rightarrow$ **1**.
* *Row 2 becomes:* `[0, 1, 1, 1]`

### Row 3: Dealing with 'c' from `text1`

* **'c' vs 'a' (No Match):** Take max of top (1) and left (0) $\rightarrow$ **1**.
* **'c' vs 'c' (Match!):** Look diagonally up-left. The value at row 'b', column 'a' is **1**. We add 1 to it $\rightarrow$ **2**.
* **'c' vs 'e' (No Match):** Take max of top (1) and left (2) $\rightarrow$ **2**.
* *Row 3 becomes:* `[0, 1, 2, 2]`

### Row 4: Dealing with 'd' from `text1`

* No letters in `text2` match 'd', so every cell just copies the maximum available from its neighbors.
* *Row 4 becomes:* `[0, 1, 2, 2]`

### Row 5: Dealing with 'e' from `text1`

* **'e' vs 'a' (No Match):** Max of top (1) and left (0) $\rightarrow$ **1**.
* **'e' vs 'c' (No Match):** Max of top (2) and left (1) $\rightarrow$ **2**.
* **'e' vs 'e' (Match!):** Look diagonally up-left. The value at row 'd', column 'c' is **2**. We add 1 to it $\rightarrow$ **3**.
* *Row 5 becomes:* `[0, 1, 2, 3]`

When the loops finish, the code returns the value in the absolute furthest bottom-right corner, which is **3**. That cell represents having checked the entirety of both strings!
